# Personal knowledge conventions

This is an editable starter combining Capture, Organize, Distill, Express with a
maintained source-backed wiki. Keep the structure useful rather than exhaustive.

## Resolve the space

Resolve the authorized Personal workspace through the available file roots.
Paths below are relative to that root, not machine-specific mount paths. Having
an inherited skill does not grant access to Personal's content from another project.
If the needed root is unavailable, explain that limitation; do not use similarly
named folders in the current project as a substitute.

## Layout

- In: original captures, sources, notes and attachments awaiting processing.
- Planning/Projects: finite goals, including goals without a runnable software project.
- Planning/Areas: ongoing responsibilities and their desired standards.
- Resources/Knowledge/sources: one processing record per capture identity.
- Resources/Knowledge/notes: linked topics, concepts, entities and syntheses as needed.
- Resources/Knowledge/index.md: links and brief descriptions for navigation.
- Resources/Knowledge/log.md: chronological meaningful knowledge changes.
- Out: drafts, briefs, reviews and other requested deliverables.
- Archive: inactive material retained for retrieval or restoration.

## Sources and identity

Give a capture a unique, stable identity. Record capture time and origin, such as
a URL, supplied file, user-authored thought, or conversation ID and entry/turn.
Keep source publication time separate from capture time. Use stable existing
revision/acquisition IDs when information tools supply them. Do not invent IDs,
hashes, publication dates or extracted content. Original captures stay intact;
processing status and assistant summaries live in a separate source record.

Use status unprocessed, pending, processed or unavailable. A saved link or an
accepted acquisition is not proof that source text was read. Record what is
actually accessible. Readability can be checked again later without overwriting
the original capture. Preserve conflicting evidence and describe uncertainty.

## Knowledge pages

Start with a short essence, then useful detail, connections and source references.
Separate source-backed claims, user views, synthesis and unresolved questions.
References point to real capture paths, revision/evidence IDs or historical
entries actually read. A topic mention alone does not require a new page.
Preserve user-authored text when maintaining a page.

## Processing and recovery

Before ingesting, look for the capture's existing source record and derived pages.
Update those instead of creating another copy. A record lists completed and
unfinished steps. Mark processed only after pages, links and index are verified.
Partial edits are not atomic; leave a truthful record and resume unfinished work.
Read current notes before changing them. Stop and reconcile if another edit makes
the intended replacement uncertain.

## Navigation and logs

The index is a linked catalog with one-line descriptions. The log records ingests,
saved syntheses, reviews and repairs with time, changed paths and unresolved work.
Do not log every ordinary reply. If a referenced file moves, update its references
and check them. Templates in skill packages are starting points; adapt them to
the user's conventions instead of overwriting an established format.
