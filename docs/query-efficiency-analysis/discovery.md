# Discovery and Relay query analysis

Status: source analysis, no implementation. Checkout `7bc567c`; runtime source baseline `fc36351f239b62984363ababaa1de1139402aafb`. All counts below are explicit JDBC statements for named branches, **excluding transaction begin/commit, JDBC driver protocol, access-layer repository calls and SQL statements executed inside stored functions unless stated otherwise**. A single JDBC statement can still perform many SQL function calls or correlated scans. Counts are source derivations, not benchmarks. Proposed counts name the necessary semantic assumptions; they are not measured outcomes. Existing plans remain proposals.

Cache verdicts describe current admission feasibility: **operation-local** reuses a snapshot within its actual consistency boundary; **share-immutable** has a defensible immutable DTO identity but still requires the proposed bounded cache foundation; **cache-blocked** lacks source-version/dependency/current-authority proof; **no-cache** is active concurrency or execution authority. Java records alone do not establish deep immutability or database freshness. No production database or network was queried by this analysis agent.

## JdbcInformationCatalogueRepository

**Path:** [facets entry](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/ws/InformationFrames.java#L355) → catalogue facets; [status caller](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/information/InformationCatalogue.java#L820) → [readable metadata projection](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/information/JdbcInformationCatalogueRepository.java#L107); [window caller](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/information/InformationCatalogue.java#L715) → text plus row. [facet SQL loop](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/information/JdbcInformationCatalogueRepository.java#L275) executes eight facet statements plus tag graph and total; typed view adds two. **D01:** the same authorized candidate filter is therefore embedded 10/12 times. One materialized authorized candidate relation feeding all aggregates can reduce 10/12 JDBC statements to one, assuming equivalent per-facet limits, empty values and one valid read snapshot; it does not prove one permission-function invocation per row without inspecting its plan.

**D02:** readable status performs readable, metadata, owner-row, steps, two progress aggregates and inputs: seven statements, plus owner event history, two report queries, and `d` extra full `row` loads for configured derive fingerprints. `steps` reads *all generations*, so `d` is not necessarily one. Metadata already contains `author` and `document_type`; owner/derive reads unnecessarily transfer extracted text. Reusing the authorized metadata row removes its immediately repeated metadata query; typed metadata reuse removes another `1+d` content-bearing reads, provided consistency is defined. **D03:** window does readable + text + row; text and row both select extracted text although only type/subtype are needed from row. One authorized text/type projection replaces three statements under the same disclosure fence.

The row/revision IDs are indexed, but [event schema](../../plowshare-server/src/main/resources/db/migration/V83__information_lifecycle.sql#L64) only gives events a sequence primary key; revision-filtered ordered history lacks that composite key in the migration search. Tag GIN does not index the joined reconstructed full-text expression. These index candidates require actual plans. Blame traces facet looping to `f78e4f04`, typed extension to `49fdab28`, and the window double-read to `d38d55f4`; PR72 did not introduce them.

**Cache:** Snapshot is immutable scalar/string data, but revision generation misses tags, policy, stage progress and allowance changes; metadata/status has several writers (processing, navigation, projection reuse, content redaction and catalogue). No shared current-authority/dependency fence exists. Admission is blocked; operation-local metadata/text reuse is immediately viable. Locks, command leases and current allow decisions remain authoritative.

**D29, expanded helper budget:** the earlier `7+d+o+2r` counts **catalogue-owned statements only**. Every readable step calls fingerprint, which invokes [configuration supplier](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/information/InformationConfig.java#L337) afresh. [fingerprint construction](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/information/InformationConfiguration.java#L85) calls [dual fingerprint](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/embedding/DispatchingDualEmbeddings.java#L65); when dual embeddings and both targets are configured, this resolves two targets, each as slot SELECT plus immutable descriptor find: **4S additional JDBC statements** for S returned visible step rows. Under that explicit configuration, expanded status is `7+d+o+2r+4S`, still excluding access-layer SQL. Capturing one fingerprint map per nonempty status step set reduces helper reads `4S→4` (saves `4(S−1)`), provided one operation intentionally uses one configuration snapshot. It also avoids repeated [filesystem refresh](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/agents/ReloadingGlobalAgents.java#L36): writable global agents/bots are each resnapshotted S times when durable layout is enabled; file counts/bytes are unknown and are not counted as SQL. The map supplier refresh dates to `fb790391`, and dual fingerprint target lookups to `f78e4f04`. These are confirmed cross-owner amplification, distinct from PR72 and from required paid-operation authority checks.

## JdbcInformationNavigationRepository

**Path:** [navigation entry](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/information/DocumentNavigation.java#L100) → `JdbcInformationNavigationRepository.documents/facets/relationships`; [facet loop](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/information/JdbcInformationNavigationRepository.java#L390) and [relationship page](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/information/JdbcInformationNavigationRepository.java#L534) are the actual aggregate/page sites. **D04:** facets always includes both content-type dimensions: ten aggregate dimensions, graph, total =12 independent candidate selections, even when no typed facet is selected. Same optimization assumption as D01 yields one statement, not a claimed speed ratio.

**D05:** relationships first selects source readability (1), selects paged edges (1), then [per-neighbour selection](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/information/JdbcInformationNavigationRepository.java#L497) for each neighbour. A readable neighbour costs1; unavailable costs2 (failed readable + visibility); locked costs3 (plus label). Thus `Q=2+R+2L+U`, where `m=R+L+U`, and `2+m≤Q≤2+3m`. Even duplicate neighbour IDs are independently resolved. A bounded join/lateral result classifying readable/locked/unavailable neighbours in the same snapshot can remove per-edge round trips; hidden-neighbour predicates must remain *before* paging. The stored functions still perform work, so one SQL statement is not automatically one authorization evaluation. Blame locates this loop in `0c199dae`. `save` also rereads a successful write; `RETURNING` eliminates that second statement.

[graph indexes](../../plowshare-server/src/main/resources/db/migration/V147__document_navigation_policy.sql#L22) provides partial source/target indexes on active edges, matching direction filtering; ordering additionally uses edge ID and optional relation, so sorting/index benefit needs plans. `policy` separately reads version/settings and inherited policy; `setPolicy` loops over effective-policy comparisons, but those before/after reads enforce no-widening and cannot be discarded as stale-check waste.

**Cache:** relationship/saved-view versions guard their own edits, policy version guards one policy row. None covers changed heads, inherited platform/project policy, references, principal revocation or list membership. Current DTO records carry versions but do not make a shared graph authorization snapshot valid. Navigation mutations, catalogue heads/audience/deletion and obligation triggers are additional writers. Cache blocked; reuse neighbour/policy snapshots only within the existing repeatable-read/locked operation, never across its authority boundary.

## JdbcScheduleDefinitionStore

**Path:** [reconcile caller](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/events/FileScheduleDefinitions.java#L188) reads old files, parses each filesystem definition, then calls [apply](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/events/JdbcScheduleDefinitionStore.java#L141). The second full collection is not required freshness: it occurs under the same source transaction lock and only adds paused override projection. Blame attributes this effective reload to `12dbdab9`, while the underlying per-file whole-source search predates it in `f78e4f04`.

A single-file projection carrying raw definition and override replaces both file-list queries with one. Under those assumptions the branch becomes three statements per apply and one initial list: `1+3N`, materializing `2N` file rows instead of `N+2N²`. A whole-reconcile transaction could reuse one collection more aggressively, but is a separate lock/failure-semantics change: the initial caller snapshot currently precedes each apply transaction and must not silently become authoritative.

[file identity](../../plowshare-server/src/main/resources/db/migration/V114__schedule_definition_files.sql#L10) already has `(source_id,name)` primary key and unique internal name, precisely supporting single-file queries. `managed` likewise spends two statements but decodes N definitions to return one. Final changed-path upsert rereads the collection; write-returning can avoid that without claiming identical unchanged/changed budgets.

**Cache:** ScheduledWork/file records have no durable mutation version. Pause override, refused status/error, runtime schedule/trigger edits and source ownership/project cascades are separate state. No shared admission proof exists. Source locks and owner checks cannot be cached; operation-local raw/effective DTO reuse is feasible now. Shared files/lists are blocked until versions and all-writer after-commit invalidation cover `apply/reject/remove/pause`, runtime stores and external changes.

## ProviderStore
