# Archive, Board, Personal, Todo and selected Relay query analysis

Source: `7bc567c2282188925ac07c81e6fcae81b41a0a40`; runtime implementation baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

These are source-derived findings, not database benchmarks or implemented fixes. Query budgets count executed JDBC statements, including lock statements, but exclude transaction begin/commit and nested work in another repository unless explicitly expanded. `N` means the named input/result cardinality; returned rows, scanned rows, function calls and JDBC round trips are different measures. Actual production row/byte counts and plans remain unknown here. Proposed budgets are conditional targets, not observed results. Index fit is checked against migrations and executed predicates; it does not prove planner choice. Positive cache verdicts identify eligibility only: shared LRU/change tracking does not exist yet, and every-writer coverage, current authorization and reconnect proof remain prerequisites. See [shared delivery foundations](../query-efficiency-plans/delivery.md).

## A01 — JdbcBoardMessagingRepository

**Confirmed N+1.** [BoardMessaging.listingPage/view](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/board/BoardMessaging.java#L1315) selects `limit+1` raw instances, checks at most `limit` visibility predicates, then performs four queries for each visible row: latest instance job, awaiting existence, pending count and instance state. [Repository listing/instanceState](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/board/JdbcBoardMessagingRepository.java#L543) separates fields from the initial instance projection. With 20 visible rows this is **81 repository statements**, before readability functions; a page-first combined inspection projection targets **1**, or **2** with a separate bounded aggregate batch. This preserves raw-row pagination before visibility filtering. Historical source snapshot `d38d55f4` contains the per-row composition; `f78e4f04` extracted persistence, so it is not evidence of a new regression.

[Delivery pages](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/board/BoardMessaging.java#L1422) cost `2+7D+S` statements: participant and ID list, then route, two participant reloads, job, delivery state, Board body and final reply per delivery; `S` adds running-job probes on unresolved branches. Repeated participants are available to reuse. Visibility work is additional. Bodies and instance requests are variable-sized; counts return scalars but scan matching routes. No actual bytes/rows examined are measured.

[Pending/final-reply indexes](../../plowshare-server/src/main/resources/db/migration/V93__board_direct_messages.sql#L36) match their predicates; [deadline](../../plowshare-server/src/main/resources/db/migration/V94__message_continuations.sql#L16) filtering is indexed. Fired-job JSON expression lookup/index fit still needs an actual plan. Reducing statements must not omit current participant/source authorization.

**Cache:** instance/route records are immutable Java values but mutable database state; they expose no durable whole-view version. Reuse DTOs within the authorized operation now. Shared admission is blocked by route/firing/approval/participant writer coverage and a complete version for defaults, awaiting, completion and list membership. Worker locks and handling decisions remain uncached.

## A02 — DigestStore

**Confirmed home-wide amplification.** [captureUnfolded](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/DigestStore.java#L56) first resolves home and lists `C` conversations, queries uncovered turns per conversation, then aggregates each of `U` turns and inserts two rows for each of `B` nonblank excerpts. A named-home lookup also occurs for every inserted digest. The exact JDBC model is `H+1+C+U+(2+H)B`, where `H=1` for a named home and zero for Global. With `C=20,U=B=5,H=1`, this is **42 statements**.

[`covered(conversation)`](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/DigestStore.java#L314) adds two queries and invokes capture for the entire home. [Retention wiring](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/ArchiveConfig.java#L256) calls it per conversation: after all turns are covered, each eligible conversation still costs `C+H+3`; `K` same-home checks repeat that work `K` times. This behavior is present in public snapshot `cd7f68ab`, not a demonstrated recent regression. A conversation-bounded set operation plus coverage result targets **2–3 statements per requested conversation**, or one home capture plus bounded coverage batch per sweep; moving loops inside a function without set operations does not reduce internal work.

[Digest keys](../../plowshare-server/src/main/resources/db/migration/V29__memory_digests.sql#L12) cover home/depth and span conversation leading columns, but range overlap and correlated `NOT EXISTS` still need plans. `get/roots/children` select `d.*` though Node maps five fields: embedding/text columns cross JDBC unnecessarily. Excerpt `left(content,4000)` bounds each entry, not total entries per turn.

**Cache blocked:** Node is immutable, but [`refresh`](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/DigestStore.java#L363) changes summary/stale state without incrementing `revision`; `digest_dirty` increments only on dirtying. Memory/fold triggers also write nodes. Thus `(id,revision)` cannot version every current snapshot. Source privacy, new parents/root membership and trigger ancestors require complete after-commit coverage before shared admission.

## A03 — MemoryStore

**Confirmed per-entry validation.** [Learning require](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/MemoryStore.java#L166) executes a scope query, a conversation/safety query and one EXISTS per supplied entry: `N+2` statements. [pin then lock](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/MemoryStore.java#L134) intentionally validates twice, before work and under source/privacy locks. For a nonnull account and one successful ordinary lock phase, those phases cost `2N+10` statements before saving: **50 at N=20**. A bounded cohort-validation statement per phase targets **8** total while retaining both freshness boundaries; collapsing them to one pre-work allow would be incorrect. [provenance](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/MemoryStore.java#L240) separately inserts `T` distinct turns and can use a bounded batch. The validation loop originates in `0b495f97` (scoped SYSTEM memory writes), without measured evidence it caused a UI regression.

The entry checks return booleans but resend every expected content string in each phase; input transfer grows with summed content size. Table locks are SQL statements with no hydrated rows and are not disposable duplicate reads. [Usage](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/MemoryStore.java#L124) already derives a new immutable Memory after an authoritative counter update, avoiding refetch. Count/index versus body projections are separate; vector recall returns full Memory bodies. Primary entry keys fit ordinal validation; state/home and profile-vector matching are distinct plan questions. [Safety functions](../../plowshare-server/src/main/resources/db/migration/V83__information_lifecycle.sql#L315) traverse provenance/readability, so one statement can still invoke many function reads.

**Cache blocked:** protocol Memory copies immutable values but exposes no whole-row version. `embedding_source_revision` versions embedding inputs, not usage, lifecycle, home or privacy. Usage, Archive saves, embedding jobs and provenance/information triggers are other writers. Shared body/TOC snapshots need separate complete versions, collection membership and live privacy fences. Cached reads must not bypass mandatory usage or lock admission.

## A04 — JdbcProjectMembers

**Confirmed repeated authority.** [`access`](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/JdbcProjectMembers.java#L182) calls `mayAdminister`; the admin branch calls it again through `managementAccess`, then reads members and 25 audit rows: **4 statements → target3** with one current operation authority result. The non-admin named-project path resolves existence, calls `requireRole` and then calls `role` again, followed by members and optional manager audit: **5 →4**, or **6 →5** for managers. `managementAccess`'s non-admin fallback adds another check. Reusing a role within a defined snapshot removes an actual repeated function call, not current authorization itself. Role duplication is visible in public snapshot `f78e4f04`; the administration round trip was added by `b234e132`.

[Mutation helpers](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/JdbcProjectMembers.java#L324) additionally load project name despite callers holding it, repeat administration checks and count effective managers. The post-mutation manager count and project row lock protect concurrency and cannot be replaced by a pre-mutation cached count. Role reads call `authority_project_role`/`service_project_role`; their internal grant/account fan-out is unknown here, so statement reductions do not quantify total SQL saved.

The member projection returns all `M` grants ordered by handle and manager history at most25; scalar role reads are narrow. Project/name and member composite keys fit equality lookup; [audit index](../../plowshare-server/src/main/resources/db/migration/V110__project_roles.sql#L17) fits project/latest-ID ordering. No additional index is proven missing.

**Operation-local only:** Access/Grant DTOs describe mutable authority with no complete authorization generation. Account disable, service ceilings, grant expiry/revocation and membership writers change effective roles independently. Notification delivery cannot guarantee immediate revocation; cache admission of allows/manager counts/locks is rejected. A safely fenced inspection snapshot is possible later, but requires every-writer authority/version proof and reconnect bypass.

## A05 — JdbcRelayPortRepository

**Confirmed polling and repeated read.** [consume](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/JdbcRelayPortRepository.java#L43) issues topic lock, database-clock and locked-batch queries, plus delegated subscribe/read. A live batch retry by its owner performs the requested-limit read then immediately replaces it with a 100-item read: `3+S+2R` statements rather than `3+S+R`, where [JdbcRelayRepository](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/JdbcRelayRepository.java#L153) expands both `S=3,R=3`: **12→9 statements** for this retry, excluding authority. Ordinary empty consume is **9** statements. Choosing the correct read after inspecting Issued removes one full read, retaining exact token boundary and gap detection. BUSY still needs authoritative seen state. `SELECT *` on issued transfers its three key columns in addition to mapped fields; clock could be returned alongside that locked row, but preserving database-time semantics is essential.

[ProjectRelayPorts](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/ProjectRelayPorts.java#L139) repeats authority/project resolution and consume every100ms while empty. `A` attempts cost `A×(authority+9)` plus any topic registration; `A` is approximately one initial attempt plus wait duration divided by100ms **only if query/scheduling time is negligible**. A notification-backed wait targets one initial and one wake/deadline reconciliation rather than this fixed cadence; expiry still needs timers. Polling appears in `4f25f68f`, so it predates the present audit.

[V131 primary key](../../plowshare-server/src/main/resources/db/migration/V131__relay_sdk_ports.sql#L3) exactly matches batch equality/locking; no new index is warranted from this source. Returned event bytes depend on Relay's bounded prefix; reading twice decodes duplicate candidates, but actual bytes are unknown. Topic-before-batch locks, lease/token/fence checks and acknowledgement idempotency are necessary state transitions.

**No cache for consume/ack decisions.** Batch DTO is immutable but mutable ownership, expiry, offsets and acknowledgements have no reusable authorization version. Only underlying immutable publications may be shared by their owning repository after current retention/access fences. LISTEN/NOTIFY remains a wake hint with durable reconciliation and reconnect recovery, not a receipt or replay instruction.

## A06 — JdbcHostedToolScopeRepository

**Confirmed Binding rehydration.** [`lease(id)`](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/tools/JdbcHostedToolScopeRepository.java#L161) calls `find` then queries worker state. [workerStatus/register/renew](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/tools/OwnedHostedToolScopes.java#L389) already loaded the same Binding, sometimes under `FOR UPDATE`. Status therefore uses **3 reads → target2**; renew uses **3 reads+1 write →2 reads+1 write**, excluding owner/executor checks. Passing the locked immutable binding and generation eliminates a repeated JSON definition decode while still comparing worker generation. A nonlocked status read needs a coherent binding-worker snapshot rather than blindly trusting an earlier DTO.

[`connections`](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/tools/OwnedHostedToolScopes.java#L511) starts with `N` bindings and repeats lease's two queries for each, before credential inspection/catalogue reads: **1+2N →1+N**, or **2** for a bounded binding/worker batch. Current session/credential/catalogue checks remain additional. List decodes at most4097 definitions before its caller rejects more than256, so overfetch can include thousands of JSON definitions, credential subjects and tombstone rows. Actual retained cardinality and bytes are unknown. V140's route and binding keys fit equality; its nondeleted owner/scope index does not fully cover tombstone-inclusive owner/ID listing.

**Operation-local reuse now.** Binding is an immutable record graph with explicit monotonically advanced generation on ordinary save, but worker lease writes do not bump Binding generation; socket/session liveness and credential policy are external dependencies. [Project deletion trigger](../../plowshare-server/src/main/resources/db/migration/V140__hosted_tool_scopes.sql#L43) also withdraws bindings/workers. Full Binding/Lease caching is rejected for authority/liveness; a sanitized definition projection could later share `(database,binding,generation,projection)` with current authority and all-writer invalidation. Reconnect and expired leases require authoritative reconciliation; no missing cache entry permits registration replay.

## A07 — JdbcApplicationDeploymentStore

**Confirmed duplicate retained release.** [commit](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/JdbcApplicationDeploymentStore.java#L127) loads the active Retained value for destination/writable-area checks, then reloads it at line143 for its placement. Both run under the same project transaction lock. Hoisting the first DTO saves **one SELECT per active replacement**, independent of cache. Under existing named project, active replacement and `install=true`, local/helper-expanded core costs9 statements (identity lookup, project lock, receipt, head, two release reads, release/head/receipt writes), targeting8; delegated owners add more. `0c2e57c7` introduced both calls. No UI latency impact is measured.

[release](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/JdbcApplicationDeploymentStore.java#L85) uses `s.*` but maps release UUID/digest/count plus destination/placement, transferring unused project ID/created-at. Each duplicate also repeats JSON decoding. [status](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/JdbcApplicationDeploymentStore.java#L196) returns at most100 releases in one head/catalog snapshot; active-first ordering is semantically significant. Receipt identity checks, expected-head comparison and activation locks are necessary, including when status is in memory.

**Share immutable retained content only:** Retained/Release values are immutable records, with revision UUID an explicit identity and no normal UPDATE writer here. `(database,projectID,revision,projection)` can identify retained metadata; administrative replacement/delete protection is not yet a proven immutability contract. Heads/status have no complete catalog generation. Project activation, identity/acting changes, schedules and maintenance are cross-owner invalidation dependencies. Publication must follow the enclosing commit, current access and FileStore resolution must remain authoritative, and reconnect must bypass uncertain heads. No cached receipt absence permits reactivation.

## A08 — JdbcPassageRepository

**Confirmed per-passage writes.** [publishBatch](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/JdbcPassageRepository.java#L249) locks owner and queue, optionally deletes old passages, loops over `P<=16` individual INSERTs and updates queue, optionally copying a legacy digest vector. Exact cost is `3+P+D+L`; at `P=16,D=1,L=0`, **20 statements → target5** using one bound multirow insert, retaining two locks, delete and queue update. JDBC batching may reduce wire exchanges but still executes P statements; do not report that alone as one SQL statement. The loop is present in public snapshot `f78e4f04`.

[coverage](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/JdbcPassageRepository.java#L420) executes three correlated passage subqueries per eligible source in its profile path: nonempty, no missing vector and count. The planner may transform them; actual invocation count is unknown. Rank/coverage add a named-home lookup, and constrained paths invoke information safety per candidate. `pending` returns at most8 full source texts, so row bounds do not bound text bytes; publish limits16 passages but vector/string lengths still matter. [V79 keys/index](../../plowshare-server/src/main/resources/db/migration/V79__retrieval_passages.sql#L3) support owner/passages equality and status/retry, but pending's `status<>ready OR generation differs` plus retry/order is not a simple equality-prefix use. Vector profile operator/column/index fit requires generated-plan inspection.

**Cache blocked for composite state:** Source has text hash and progress; hash alone does not version ready/error/position or embedding-space cutovers. Match contains immutable scalar/text fields, while digestVector exposes mutable `float[]` requiring copying. Entry/digest triggers delete/recreate retrieval sources and embedding workers update vectors outside this owner. Immutable passage DTOs need source hash plus generation/space/projection and current privacy; coverage lists need membership versions. Owner-before-queue locks and requireSource are authoritative source-change fences, not wasteful reads. No shared repair/lease admission is safe.

BoardTopic and seat views change with allowances, lifecycle, wakes and watermarks; no complete returned version exists. `seq` orders messages but does not version a whole topic/seat projection. BoardMessaging, firing, allowance and notice writers bypass individual methods. Current authority and live claim/alert/seen predicates remain uncached; every-writer commit invalidation, list membership and reconnect proof are missing.

## A12 — ProposalStore

## A13 — TodoStore

**Batch amplification, with a conditional reload candidate.** [TodoBoard.apply](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/todos/TodoBoard.java#L126) holds a baseline and complete working map, writes `I` inserted and `U` changed existing items, invokes effects, then [reloads](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/todos/TodoBoard.java#L270) after callbacks. Exact store count is `2+I+U`; at20 changed rows, **22** statements, excluding stage/orchestration effects. One bounded multirow insert and one set-based optimistic update target at most4 store statements with the fresh final list retained. Removing that final read would save one more only after proving callbacks/triggers cannot change returned rows; current source alone does not establish that.

[The UPDATE](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/todos/TodoStore.java#L56) compares previous `updated_at`; every intended row must match or the entire transaction rolls back. This is concurrency protection, not a wasted reread. List transfers all text/summary/status fields and is bounded to100 items by TodoBoard, not by SQL itself. [V45 index](../../plowshare-server/src/main/resources/db/migration/V45__todos.sql#L35) covers conversation,parent,position but lacks the ID final tiebreak; NULLS FIRST order may still need sorting. A100-row cap makes another index an unproven priority. There are no nested SQL permission functions in TodoStore itself.

**Operation-local:** TodoItem is immutable and carries microsecond-truncated updatedAt as an optimistic item token. That token does not version inserted/deleted list membership or every multi-row effect. Stage seeding/orchestration and callbacks are additional writers/dependencies. Shared list admission requires durable list generation and current conversation visibility, every-writer post-commit invalidation and reconnect proof. Cached `locked`/stage values must not authorize edits; preserve baseline predicates and no publication on rollback.

## A14 — JdbcPersonalSpaceRepository

No shared reservation/lock/eligibility cache is safe. Stable name/ID metadata could later share only behind complete identity/version invalidation and reconnect recovery, with current access fences.
