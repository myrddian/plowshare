# JdbcProjectMembers

Status: Proposed. Source baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[This owner](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/JdbcProjectMembers.java#L137) resolves effective project/service roles, administration, member lists and audit history; transactional assignment/removal locks the project, changes authority grants and membership, audits and protects the last enabled manager. ProjectStore and authorization consumers use `ProjectMembers`. Ordinary, Personal and client-private scopes have deliberately different rules.

Confirmed repeated work: `access` calls `mayAdminister`, then `managementAccess` calls it again on the admin path; the non-admin path calls `requireRole`, then calls `role` again. `protectManager` resolves `projectName(id)` although its callers already hold the project name, and administration checks repeat before/after mutations. Refactor helpers to accept a typed operation authority snapshot and resolved project identity. Reuse only across a declared valid snapshot/lock boundary: the final manager check is a concurrency invariant and must remain authoritative after changes. A table-returning function can resolve administration/effective role once for access assembly, while set-based membership/audit reads preserve manager-only audit disclosure. Do not merely wrap repeated `authority_project_role` calls. [V110](../../plowshare-server/src/main/resources/db/migration/V110__project_roles.sql#L17) already indexes recent project audit order.

Shared caching is low priority for effective allow decisions. Immutable `Grant`/`GrantChange` inspection DTOs may be tracked by database/project/principal/projection/page plus membership and authority generation returned in the read. Dependencies include account enabled/kind/admin status, service credentials and ceilings, project Personal/client identity, authority grant ancestry/expiry/revocation and membership/audit collection changes. Cover assignment/removal here plus account, acting/application and authority writers and database triggers. Invalidate after commit; never publish rollback state. Immediate revocation requires a current authoritative fence, not a listener-health assumption. Never cache manager counts, project locks or mutation admission. Reconnect bypasses this namespace until baseline recovery; use the proposed bounded LRU.

First enforce mock query budgets: one effective role and one administration resolution per consistent access operation. Test service ceilings, Personal isolation and manager-only history. Focused PostgreSQL tests are needed if changing routines/locking/versions: concurrent last-manager removal, account disable, grant revocation and rollback. Historical function timing elsewhere motivates measuring this owner; it is not proof of its own latency.
