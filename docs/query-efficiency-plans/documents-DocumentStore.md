# DocumentStore

Status: Proposed; no implementation. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Source](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/documents/DocumentStore.java#L406) owns document/hierarchy/chunk/reference/code projections for ingest, summarization and `RetrievalService`. Reads cover document identity, pending embeddings/summaries, hierarchy/references/text, vector/lexical/hybrid results, chunk ancestors, list/count and coverage/ranking. Writes reconcile paragraphs/chunks, replace hierarchy/references, attach summaries/vectors and code outlines. Scoped/profiled copies enforce current information selection, corpus, embedding space and optional publication fences.

**Confirmed composition:** [RetrievalService](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/documents/RetrievalService.java#L408) computes coverage before provider IO and may compute it again at disclosure; the latter can be a valid freshness fence, so combine it with authoritative result assembly or explicitly retain the same snapshot rather than blindly deleting it. Dual-profile search also performs an initial coverage read before the later search path. State the intended consistency boundary and share one coverage result within it. List rows calculate four correlated hierarchy counts per document; batch counts for the selected page or maintain verified projection counts. `hierarchy` already uses two set-based queries, not a query per chapter. Ingest writes/code-symbol/chunk attachment loops are candidates for JDBC batching while preserving stable identities and transaction rollback.

[V18](../../plowshare-server/src/main/resources/db/migration/V18__documents.sql#L198) supplies paragraph reconciliation identity; [V21](../../plowshare-server/src/main/resources/db/migration/V21__chunk_text_search.sql#L167) supplies chunk lexical GIN; [V26](../../plowshare-server/src/main/resources/db/migration/V26__hierarchy.sql#L224) indexes section order. Inspect document/paragraph/chunk join and substring naming plans before adding indexes. A trigram index may help leading-wildcard name search but requires an explicit migration/extension decision. Preserve `EmbeddingIndexPlan` ownership of exact/approximate vector policy and post-filter recall. A typed result-plus-coverage routine can save round trips; it must retain authorization and embedding version fences.

Track immutable content DTOs by database, document/revision, content/text/source version and projection. Mutable summary/vector/hierarchy/list/coverage DTOs need their own durable versions plus principal, full selection/facets/read boundary, corpus, active slot/space/version and query parameters. Do not cache result sets under source name alone. Every write/attach/code-outline method, information extraction/rebuild/copy/deletion, embedding activation/publication, policy/tag/input/reference changes and external writers invalidates affected content/query-set dependencies after commit. New/removed rows invalidate coverage and lists even when absent from old results. Shared DTO cache uses bounded expected O(1) LRU, byte-weight admission and oversized bypass; current authorization cannot wait for notifications. Leases/fences remain authoritative.

First fix request-local projection reuse and batch SQL, then connect shared versions/invalidation and client scoped hints. Mock budgets should prove no duplicate coverage in one declared snapshot, constant list-count scans and batch ingestion calls. Later focused PostgreSQL tests cover result/recall equivalence, stable paragraph identities, revocation, copy/rebuild rollback, vector/index plans and fill/invalidation races. Measure database execution separately from serialized WebSocket waiting.
