# JdbcHostedToolScopeRepository

Status: Proposed. Source baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Hosted scope persistence](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/tools/JdbcHostedToolScopeRepository.java#L87) reads bindings/routes, locks projects/bindings, saves exact advancing generations, manages worker leases and records mutation reservations/receipts. OwnedHostedToolScopes owns current account/executor/session/credential/catalogue checks. UUID tombstones cannot be adopted, and uncertain mutation absence never permits replay.

Confirmed duplicate hydration: `lease(id)` first calls `find(id,false)` although worker registration/renew/status/available callers already hold a Binding, then fetches its worker. `connections` lists bindings and repeats this pair per binding, plus credential/catalogue checks. Add a typed lease lookup using the supplied binding/generation or a bounded binding-plus-worker batch projection; compare generations in SQL and retain authoritative lock checks on mutations. Reuse the already decoded immutable definition in an operation. [V140](../../plowshare-server/src/main/resources/db/migration/V140__hosted_tool_scopes.sql#L2) already has binding/route/worker keys and a partial owner/scope unique index; list includes tombstones and orders ID, so evaluate `(project_id,owner,id)` only against actual retained-size plans. Its repository cap 4097 versus service cap 256 may decode many definitions only to refuse; a narrow limit/count admission projection could avoid that work. Stored routines are optional for cohesive lookup/save+receipt, not credential admission.

Initially exclude worker leases, socket/session IDs, credential subjects/material, eligibility and mutation reservations from shared caching. A sanitized immutable Definition/Binding inspection projection can use database/project/binding/generation/projection keys and owner-scoped disclosure. Existing generation is useful but must not be treated as versioning live worker/session or provider-credential state. Depend on project deletion/name, binding enable/delete/definition, provider connection and credential policy, account/authority changes, catalogue generation and list membership. Cover save, clearLease/lease, project-withdrawal trigger, provider/credential and all external writers after commit. Current executor/session/credential fences remain mandatory on hits. Reconnect bypasses uncertain generations; bounded shared LRU must not retain private worker DTOs as generic cache values.

Deliver supplied-binding/batch reuse first, list projection work second, sanitized tracking third. Notifications can wake catalogue/status refresh but do not establish worker liveness; expiry and disconnected sessions require current checks/timers. Mock bounded queries independent of binding count and no repeated definition hydration. Changed SQL requires focused PostgreSQL generation conflict/tombstone, worker replacement, receipt reconciliation, project withdrawal and rollback/invalidation tests. See [delivery](delivery.md).
