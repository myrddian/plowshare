# JdbcRelayNativeRepository

Status: Proposed; no implementation. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Source](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/JdbcRelayNativeRepository.java#L40) adapts existing firing inboxes for `RelayInternalWorkers` and `Dispatcher`. Bind checks a queued owning wake joined to board/project authority, subscribes, inserts a consumer and verifies its binding. Routes checks consumers or queued topic firings. Ready joins bindings/offsets/topics and checks pending firings using keyset discovery. Advance/gap recovery fence the consumer before and after offset changes. Claim checks binding, serializes target, rechecks lease, validates oldest firing and busy state, then guarded-starts. Prune retains live leases and pending/uncertain inbox work.

Ready polling scans unchanged discovery state; add notification-triggered targeted discovery for outbox/publication/firing changes, retaining bounded rotated sweeps and time-driven lease/retry recovery. Request-local reuse may retain a validated binding while the same consumer lock protects its identity; final lease-expiry checks remain required. Bind can use insert `RETURNING` plus conflict-path verification rather than unconditional reload. Claim reads busy state and repeats equivalent exclusion in its guarded update: evaluate removing the preliminary busy query only if tests preserve historical DTO validation and unique running-target behavior.

[V125](../../plowshare-server/src/main/resources/db/migration/V125__relay_native_wake_consumers.sql#L6) supplies binding identity, target and gap-age indexes; firings already has queued-target and one-running-target indexes. Measure the ready correlated existence and concatenated keyset cursor before changing to tuple comparison/index variants. A narrow typed native claim routine is optional if it preserves consumer-before-target lock order and post-wait time fences.

Do not cache routes/ready eligibility, consumer leases, gap proof or firing claims as runtime authority. Optional display binding DTOs need database, system topic/subscriber incarnations, target/account/project and binding version; current private-topic disclosure stays server-owned. Bind/prune, subscription/offset changes, firings/board lifecycle writes, conversation/project deletion and external writers invalidate item/discovery dependencies after commit. Immutable wake publications can reuse broker DTOs separately. Use proposed bounded tracked DTO/LRU only for eligible displays, with [delivery contracts](delivery.md) governing durable hints and reconnect recovery.

Mock budgets should prove unchanged discovery is suppressed after hints without omitting fallback sweeps, and avoid duplicate binding hydration within one protected operation. Later focused PostgreSQL tests cover target concurrency, waiting past expiry, gap recovery, removal fences, wake validation, rollback and missed notifications. Relay continues to coordinate availability; firings retain the owning execution lifecycle.
