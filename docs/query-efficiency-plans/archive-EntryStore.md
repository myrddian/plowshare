# EntryStore

Status: Proposed. Source baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[EntryStore](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/EntryStore.java#L1247) owns conversation append, invocation/fallback and handle lookup, payload ejection, complete versus current/historical model projections, bounded transcript pages, text search, folding/supersession and learner discovery/acknowledgement. Compaction, Transcript, conversation views, retrieval and retention consume different projections; a complete log cannot replace the reduced model history indiscriminately. Append already uses an advisory transaction lock plus `INSERT ... SELECT MAX ... RETURNING`; retain its lock-before-snapshot ordering.

[`page`](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/EntryStore.java#L2066) reads reach, count and rows; this has an explicit append-consistency reason, since count/page are bounded by the captured ordinal. Compare a single typed snapshot function/materialized candidate CTE that returns reach/count even for an empty page, rather than deleting the reach check. Reuse caller-supplied `asOf` and page results within an operation. Account-scoped entry methods run readability checks separately; measure duplicated same-log authority work across composition and share it only within an equivalent current snapshot. Search computes coverage/matches then ranked hits; compare one authorized candidate selection while preserving ejected/recorded-only coverage and post-limit snippet generation. `markLearned` already batches ordinals; preserve it. [V23](../../plowshare-server/src/main/resources/db/migration/V23__entry_text_search.sql#L151) already provides the text GIN index. Evaluate `(conversation_id,turn_ordinal,ordinal)` or a projection-specific partial index only against existing primary-key, learner and retained-payload plans. Avoid indexing full payloads by default.

Entries change after append: superseded, ejected, learned and derived embedding states make ordinal alone an incomplete version. Track immutable EntryRecord/page DTOs by database, conversation, ordinal or as-of cursor, projection, kinds/bounds, principal/read scope and durable entry/projection generation. Historical rendering also depends on child conversations referenced by tool calls. Lists/search depend on new entries, fold seams, payload withdrawal, conversation home and information privacy membership. Every append/fold/eject/learner, retention, retrieval and database-trigger writer must invalidate after commit. Separate retained content from mutable readability; current revocation fences still apply on hits. No cache substitutes for append locks, authoritative ejection/learning predicates or durable accounting. Reconnect bypasses protected projections until durable change recovery; byte-bound oversized logs and in-flight loads in the shared LRU.

First remove repeated composition reads; second consolidate measured page/search candidates and indexes; third add versioned tracking. Mock query budgets and reuse distinct log/model projections correctly. Changed SQL requires focused PostgreSQL append races, captured-reach pagination, intra-turn folds, ejection/privacy, full-text equivalence and rollback/invalidation tests. Existing narrow projection work should be retained, not replaced with full-log caching.
