# JdbcRelayPortRepository

Status: Proposed. Source baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[SDK port persistence](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/JdbcRelayPortRepository.java#L38) locks topic then issued batch, subscribes/reads the group, uses database time and issues a 30-second token/fence; acknowledge verifies account/consumer/token/fence/gap and advances the exact boundary once. ProjectRelayPorts performs current configured direction/group and project membership checks. These operations mutate subscription/batch state and must remain ordered, even though consume returns data.

Confirmed repeated reads: consume reads the Relay group at the requested limit before inspecting an outstanding same-consumer batch, then rereads at 100 to reconstruct its exact boundary. Choose the necessary read once after inspecting the locked Issued DTO, retaining BUSY/current-seen behavior and retention-gap detection. Join database time into the locked batch projection where possible to avoid a separate `clock_timestamp()` round trip; do not replace it with unsynchronized application time. Narrow `issued` from `SELECT *`. [V131](../../plowshare-server/src/main/resources/db/migration/V131__relay_sdk_ports.sql#L3) has the exact batch key; no new index is indicated for primary-key locking. A typed stored consume/ack routine is a candidate only if it preserves topic-before-batch lock order and existing Relay ownership.

[ProjectRelayPorts.consume](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/ProjectRelayPorts.java#L153) polls every 100 ms while empty, repeating authority, project and consume work. Add a bounded notification-backed wait outside database transactions, waking on publication plus timeout/reconciliation; recheck current authority and token state at execution. Time expiry still needs a deadline. Do not cache outstanding batches, leases, absence, fences, acknowledgements or executable group offsets. Reuse only immutable publication payload DTOs from the Relay owner, keyed by database/scope/topic generation/position/projection, with current retention/access validation. All publication/retention/subscription/batch/project/authority writers contribute after-commit invalidation/wake evidence. Listener reconnect resumes durable reconciliation, never assumes notifications are the ledger. Shared LRU cannot authorize consume or acknowledgement.

First remove the duplicate read and clock round trip where correct; second replace empty polling with bounded waits; third reuse eligible publication bodies. Mock one necessary group read per branch and no SQL held during waits. Changed SQL needs focused PostgreSQL same-token retry, BUSY ownership, byte/limit refusal, expiry, gap, stale fence, ack retry and rollback tests. See [delivery](delivery.md) for the shared foundation.
