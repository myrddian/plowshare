# ProposalStore

Status: Proposed. Source baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Proposal persistence](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/ProposalStore.java#L165) files proposals, joins memory/home for reads, lists pending and ruled-on memory IDs, conditionally settles, annotates promotion results, releases failed claims and finds selected curator rulings. PromotionQueue and proposal WebSocket/API surfaces own policy and partial-failure handling. [V2](../../plowshare-server/src/main/resources/db/migration/V2__proposals.sql#L85) already enforces one pending memory/action via a partial unique index; do not replace it with a preflight query.

Confirmed round trips: successful `propose`, `resolve`, `note` and `release` fetch the full joined Proposal after writing; `note`/`release` also read for meaningful refusals. Evaluate typed `INSERT/UPDATE ... RETURNING`, joined via a data-modifying CTE to memory/project where needed, retaining precise no-row diagnostics. Pass a just-settled Proposal to subsequent promotion accounting when its version remains valid. Conditional state predicates remain in SQL even when a prior DTO says settled: the source documents release races. A stored transition function is useful only if it removes repeated hydration while preserving constraint/error behavior. Measure pending-list/home joins before adding `(state,memory_id,id)` or another index; existing keys may suffice.

Track immutable Proposal snapshots by database, proposal ID, projection and durable proposal generation. State, resolution and settlement timestamps are not yet a complete monotonic version contract; releases clear fields. Pending/ruled-on/ruling pages depend on query membership, not just rows already returned. Invalidate on all proposal mutations plus memory home/state/project changes through PromotionQueue, Archive and every database writer. Publish only after commit and invalidate released/newly pending rows correctly. Cache reads remain behind current proposal/memory/project authority; no cached settlement authorizes promotion, and no shared cache replaces the conditional claim. On reconnect bypass until durable proposal/memory generation recovery. Use the shared bounded LRU.

First consolidate returned projections; second tune measured list plans; third introduce versioned tracking. Mock one returned DTO through resolve/promote/account composition and bounded per-item work in reconsideration. Changed SQL warrants focused PostgreSQL duplicate pending, settle/release races, failed-promotion rollback and result-equivalence tests. No automatic replay follows an uncertain mutation response.
