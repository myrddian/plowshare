# JdbcRelayForwardingHistory

Status: Proposed. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[`causation`](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/JdbcRelayForwardingHistory.java#L19) returns carried ancestry without SQL; legacy forwarding walks delivery-to-admission links one query per hop, at most 32. ForwardRelayReceiver, WorkRelayReceiver and RelayEffectBound use this proof to preserve effect bounds. Each hop checks exact scope, receiver, publish target, canonical UUID, pointer equality and inherited depth; unverifiable runtime-derived events cannot become new roots. The delivery primary key and admission composite key already support individual joins.

Keep the carried-DTO fast path. If legacy depth is material, replace the Java loop with a bounded recursive CTE/table-returning function carrying each hop's expected target and pointer. Preserve fail-closed handling for missing links, malformed identity, wrong receiver and depth overflow; a generic ancestry join is insufficient. Measure hop count separately from call frequency before adding indexes. Current stored ancestry is preferable to repeatedly reconstructing history that the publication already supplies.

A cache may track immutable verified link/ancestry DTOs under database, scope, delivery/publication identity, event fingerprint, projection and maximum-depth policy. Include admission identity/generation and target so equal IDs cannot cross scope or a stricter depth limit. Do not cache unverifiable absence indefinitely: pruning or later insertion changes proof availability. Admission/delivery retention, project deletion and every exceptional maintenance writer must invalidate after commit. A cached proof cannot extend the durable retention contract without an explicit decision; if required source proof is gone, authoritative validation or namespace expiry must refuse. Current Relay access/effect admission still applies separately. On reconnect bypass uncertain provenance until durable recovery; use shared bounded LRU only if legacy reconstruction reuse warrants it.

Mock zero SQL for carried causation, bounded legacy traversal and reuse within one effect operation. A changed recursive SQL routine requires focused PostgreSQL multi-hop equivalence, wrong-scope/target links, depth/cycles, retention and rollback tests. No new durable bus, effect replay or runtime change is part of this plan; shared foundation is in [delivery](delivery.md).
