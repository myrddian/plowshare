# JdbcInformationContentTypeRepository

Status: Proposed; no implementation. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Source](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/information/JdbcInformationContentTypeRepository.java#L57) implements the namespace registry for `InformationContentTypeService` and binding resolution. `list` loads bounded version pages, `version` optionally locks navigation/type/version in order, and `attached` joins binding/revision availability. `create` locks allocation control, inserts a version, advances control revision and rereads; `transition` locks the current version, deprecates prior active version, updates state/control and rereads. Decoding schema/presentation is repeated for every read.

Reuse decoded immutable contracts separately from mutable lifecycle wrappers. Return create/transition results using explicit `RETURNING` projections and the existing validated contract instead of a final full-schema reload. Read both type control and version data together where possible, preserving the explicit lock order. [V143](../../plowshare-server/src/main/resources/db/migration/V143__authored_information_content_types.sql#L2) already provides namespace/slug identity, type/ordinal uniqueness, immutable definition guards and a partial one-active-version index. Evaluate namespace/list pagination plans before new composite indexes. A typed lifecycle routine is optional if it demonstrably reduces round trips while preserving control-revision conflict behavior.

Cache contract DTOs by database, version UUID and definition hash; cache lifecycle/list DTOs by namespace/filter/page and type `control_revision`. Because label/description come from the type join, include their source dependency rather than treating the entire joined row as forever immutable. `create/transition`, binding attach/redact, revision deletion and any external registry writer must invalidate corresponding version, attached-binding and collection dependencies after commit. `attached` must still establish live non-redacted/non-deleted eligibility and current caller authority before disclosure. Never cache lock acquisition or expected-version admission. Use the proposed tracked immutable DTO cache with schema-size byte bounds and expected O(1) LRU.

Mock tests should prove contract decoding is shared and writes do not reread their own full result. Later focused PostgreSQL tests cover competing activations, allocation/conflict semantics, partial uniqueness, immutable triggers and notification recovery. Cache invalidation cannot make an inactive contract eligible for new attachments.
