# MemoryStore

Status: Proposed. Source baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[MemoryStore](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/MemoryStore.java#L100) owns memory rows, active/cold versus retired projections, narrow active TOC, legacy/profile vector recall, unsearchable counts, write/read pins and fences, provenance and usage telemetry. Archive/MemoryQueries/MemoryWrites coordinate it. Reads can acquire navigation/scope/table locks and record use; classify these as ordered operations, not freely parallel read-only cache hits.

Confirmed amplification: learning `require` performs one EXISTS query per source entry, and provenance writes one row per distinct turn. Replace each with bounded typed batch/set-based validation/insertion; fail if any supplied ordinal/turn/content/kind/source state differs. `pin` validates before work and `lock` revalidates under locks: retain that second admission as a documented concurrency fence. `used` already derives a returned Memory from the loaded object after an authoritative increment; preserve this reuse rather than refetching. Reuse one resolved home and query selection within a recall operation. [Navigator.evidence](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/agents/digests/Navigator.java#L366) calls Archive.get then Archive.read for an active memory; evaluate returning the authorized, telemetry-bearing snapshot once while retaining the current home/state and source fences. Inspect correlated safety-function calls and avoid loading full bodies for index/count views, which already have separate projections. A stored validation routine may combine cohort checks but cannot hide per-row loops or bypass privacy locks. [V157](../../plowshare-server/src/main/resources/db/migration/V157__knowledge_homes_and_write_authority.sql#L88) adds authority home identity; profile vector indexes must match the generated operator/column and pre-limit safety filters.

Track only immutable Memory/TOC snapshots, keyed by database, memory ID, projection and complete row/content/embedding version; result collections additionally need home/principal/query/embedding-profile and membership generations. `embedding_source_revision` does not version use counters, last-used or lifecycle, so split telemetry projections or add an explicit whole-row generation returned in the same read. Depend on memory content/state/home, provenance and source privacy, information state, scope/grants, embedding spaces and active slots. Include Archive save, usage, embedding work, promotion, triggers and maintenance as after-commit invalidation writers. No shared caching of lockRead/lock admission, current safety allows or telemetry side effects. Current revocation fences are mandatory even on hits. Reconnect bypasses protected namespaces until durable recovery; use bounded expected O(1) LRU with oversized-body bypass.

Deliver batch source checks/provenance first, then measured SQL/function/index changes, then split versioned cache projections. Mock query count independent of learning-source count, same-operation Memory reuse and mandatory telemetry. Focused PostgreSQL tests apply only to changed batching, lock/rollback semantics, privacy revocation, source version publication and ANN equivalence. Cache hits must never silently skip durable accounting.
