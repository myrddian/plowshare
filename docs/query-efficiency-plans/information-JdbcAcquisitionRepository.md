# JdbcAcquisitionRepository

Status: Proposed; no implementation. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Source](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/information/JdbcAcquisitionRepository.java#L61) implements token-fenced URL acquisition for `InformationAcquisitions`. `prior/submit` enforce request fingerprint/idempotency across acquisition and intake; submit takes a request advisory lock. `owned/list` load account-scoped tickets/status ordered by creation. `claim` locks one queued/expired-running ticket, then updates attempt/token/lease. Other writes persist retry, hooks, log, admitted revision and finish state; `retained` reads revision resource/source URI.

Narrow list/status projections: `list` currently selects complete tickets including retained content intent/hook data before returning status. Return a typed status row without decoding fields it cannot disclose/use. Carry the admitted ID and already loaded status through submit/status composition, avoiding gratuitous owned reloads when the committed result can be returned. A claim CTE using `UPDATE ... FROM (SELECT ... FOR UPDATE SKIP LOCKED) ... RETURNING` can combine claim round trips; preserve outer transaction ownership and token fences. Rechecks after network/hooks are required.

[V83](../../plowshare-server/src/main/resources/db/migration/V83__information_lifecycle.sql#L271) supplies ID and `(account,request_id)` keys but no matching acquisition list/queue index there. Evaluate `(account,project_name,corpus,created_at DESC,id)` and separate partial queued/running discovery indexes; test nullable project predicates and expired lease selectivity before migration. A stored claim routine is an alternative to the CTE, not an excuse to hide row-by-row scanning.

Cache immutable display status DTOs by database, account, ticket and transition version; list keys include project/corpus/page and collection generation. Add an explicit monotonic version returned with the status. Keep claim/fence/retry admission and active lease tokens outside the cache. Every submit/retry/claim/finish/opened/hook/admitted/finishRecords update, catalogue sanitization/deletion and external writer invalidates corresponding status/list dependencies after commit. Protected intent/provenance uses current authority fences. Use proposed tracked DTO/LRU capacity limits and durable reconnect recovery; notifications wake workers but do not replace lease-expiry timers or durable reconciliation.

Mock budgets should bound status hydration and avoid repeated status fetch after admission. Focused future PostgreSQL tests cover concurrent claim/expiry, cross-operation request collisions, rollback, exact status mapping, queue/list plans and notification loss. Keep network calls outside held locks.
