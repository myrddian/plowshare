# JdbcEmbeddingWorkRepository

Status: Proposed; no implementation. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Source](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/embedding/JdbcEmbeddingWorkRepository.java#L143) implements `EmbeddingWorkRepository` for `DispatchingDualEmbeddings`, bound repairs and publication. It reads typed source text/revision across memories, digests, documents, chunks and retrieval passages; loads active/target slot profiles and input limits; finds bounded pending sources using source revisions, staging and failure retry fences. Mutations configure slots, publish current-source vectors, retain failures/repair admission, build indexes and atomically activate complete coverage. `read` locks slot configuration and verifies index readiness before work.

**Confirmed composition:** profile mapping issues a separate `spaces.find` for every profile. `configure` reads target, updates it, then reads target again; its final result can use `UPDATE ... RETURNING` plus the already validated descriptor. Join immutable descriptors or share their tracked DTOs. Within one slot-locked transaction reuse the loaded active/target profiles; do not remove source or profile rechecks across provider IO, where they prevent stale publication. Activation's coverage checks and source table locks are correctness fences.

[V115](../../plowshare-server/src/main/resources/db/migration/V115__code_and_prose_embeddings.sql#L188) supplies staging identities and source revision guards; [V116](../../plowshare-server/src/main/resources/db/migration/V116__embedding_runtime.sql#L21) supplies failures and input limits. Measure pending scans with realistic eligible/failed populations and inspect staging/failure key use before proposing partial source-revision indexes. Existing `EmbeddingIndexPlan` owns vector index policy; avoid a second index lifecycle. A typed routine could combine slot-profile and descriptor loading, but routine wrapping is unnecessary for simple lookup reuse.

Cache immutable source text by database, typed source key, `embedding_source_revision` and projection; apply current source authorization before disclosure. Cache profile DTOs by slot plus durable slot version, input limits by space plus a new settings version, and descriptors independently. Invalidate after configure/activation/input-limit writes, all source text changes/deletions, vector publication, failure/repair state changes and external writers; invalidate coverage/query memberships too. Do not cache repair admission, readiness, locks, activation proof or index-health authority. Notifications wake repair discovery, with retry deadlines and durable recovery retained. Use the proposed tracked DTO/LRU foundation with byte bounds because source text/vectors are large.

Mock budgets should prove descriptor reuse and one committed profile result after configure. Later focused PostgreSQL tests cover source changes during provider IO, activation lock ordering, rollback, vector indexes, repair no-replay and notification recovery. Separate index-building cost from interactive query dispatch delay.
