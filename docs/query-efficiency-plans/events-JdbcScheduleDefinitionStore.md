# JdbcScheduleDefinitionStore

Status: Proposed; no implementation. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

`ScheduleDefinitionStore` serves `FileScheduleDefinitions` reconciliation and control. [Source](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/events/JdbcScheduleDefinitionStore.java#L44) registers sources using insert then ownership-checked lookup; `sources` joins project names. `files` reads and decodes every JSON definition for a source, ordered by name. `sourceOf`, `requiresDefinition` and `managed` locate runtime ownership. `apply`, `reject`, `remove` and `pause` lock the source and coordinate schedules, triggers and queued firings in one transaction.

**Confirmed waste:** `apply` reads the whole file collection to find one name, then repeats that collection read on unchanged and final-result paths. `managed` and `pause` also filter a full collection for one file. Reconciliation across N files therefore repeats collection decoding and can grow quadratically. Replace these with a typed single-file lookup on `(source_id,name)` and a source snapshot reused inside one reconciliation transaction where appropriate. Preserve the raw definition and effective pause projection together, avoiding another load just to apply `paused_override`. Return the upserted file projection with `RETURNING`; carry already-found schedule/trigger snapshots through helpers rather than looking them up again.

[V114](../../plowshare-server/src/main/resources/db/migration/V114__schedule_definition_files.sql#L10) already supplies the file primary key and unique internal name. Fix query shape before adding indexes. Registration can use an atomic upsert-returning routine only if it preserves the existing refusal for another account; no broad stored procedure is needed for ordinary reads.

Cache eligible immutable file/source DTOs by database, source ID, name, projection and durable definition/control version. Add a monotonic source/file version first; JSON equality is not a concurrency version. Source registration, apply/reject/remove/pause, schedule/trigger changes, source/project deletion and Application reconciliation must invalidate corresponding file and collection dependencies after commit. All writers, including other processes, need durable change evidence plus notification hints. Never cache the source lock, ownership admission or execution authority. Use current authority fences before disclosure/control; transaction-local reads remain local.

Depend on the shared [tracked DTO/LRU foundation](../query-efficiency-and-cache-design.md), then scoped client hints and bounded independent-read dispatch. Mock budgets should prove constant single-file reads and no full-source reload for unchanged apply. Later focused PostgreSQL tests justify only lock ordering, atomic rollback, upsert mapping, authority races and notification recovery. Measure collection cardinality, definitions decoded and query counts before claiming a speedup.
