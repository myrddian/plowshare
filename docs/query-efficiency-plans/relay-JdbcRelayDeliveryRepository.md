# JdbcRelayDeliveryRepository

Status: Proposed; no implementation. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Source](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/JdbcRelayDeliveryRepository.java#L48) implements atomic admission and branch lifecycle for `DurableRelayDeliveries`, consumer fencing, operator reconciliation and maintenance. Admission locks topic boundaries, resolves retained admission or next publication, enforces the pending bound, copies input/routing/branches and advances seen offset together. Reads rebuild admission plus ordered branch definitions, or join delivery state with copied payload/source. Claim uses ordered `FOR UPDATE SKIP LOCKED`; dispatch/renew/outcomes/reconcile lock and validate the branch. Recovery distinguishes retryable expired CLAIMED from uncertain DISPATCHING; pruning removes only fully settled old admissions.

**Confirmed extra work:** transitions load a joined payload/handler DTO, update a few state columns, then `locked` rereads and decodes the same large immutable payload again. Return changed lifecycle columns using guarded `UPDATE ... RETURNING`, combining them with the already-validated immutable input snapshot in the same transaction. Separate typed immutable admission material from mutable branch state to avoid hydrating source bytes for metadata-only lists/checks. Batch the bounded fan-out insertion (maximum 32 branches). `admitted` already loads branch definitions set-wise; preserve complete branch-order validation.

[V118](../../plowshare-server/src/main/resources/db/migration/V118__relay_delivery_admission.sql#L63), transformed by [V120](../../plowshare-server/src/main/resources/db/migration/V120__relay_scopes.sql#L20), provides ready-order, expiry and retention indexes. Evaluate the pending-state count and prune anti-join against real distributions before adding a broader pending partial index. A typed atomic claim/transition function may reduce round trips, but preserve locks, fences, receipt idempotency and backpressure.

Track immutable admission payload/routing/source DTOs by database, scoped subscription incarnation, publication position, admission identity/hash and projection. Mutable delivery displays require delivery UUID plus a monotonic transition version; fence alone misses accepted/failed/renew changes and timestamps are not guaranteed unique. Every admit/claim/prepare/renew/outcome/reconcile/recover/prune path, operator abandon/removal, subscription/project cascades and external writers invalidates affected item/list/offset dependencies after commit. Current caller authority remains required. Never cache claims, lease checks, pending-cap admission or reconciliation eligibility. Use proposed tracked DTO/LRU byte bounds, oversized source bypass and fill-generation fencing.

LISTEN/NOTIFY can wake ready delivery discovery; retain lease timers, durable recovery and no-replay uncertainty. Follow [delivery contracts](delivery.md). Mock budgets should prove one payload hydration per transition and batched fan-out writes. Later focused PostgreSQL tests cover competing claims, atomic admission/offset rollback, expired dispatch uncertainty, result equivalence, current revocation, pruning and notification loss.
