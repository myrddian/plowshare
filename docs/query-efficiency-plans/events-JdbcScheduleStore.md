# JdbcScheduleStore

Status: Proposed; no implementation. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Source](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/events/JdbcScheduleStore.java#L63) implements `ScheduleStore` for `Ticker`, `RelayScheduledPublication` and file reconciliation. `define` already uses owner-guarded upsert `RETURNING`; `list/find` return narrow schedule records. `due` filters unpaused due rows and rechecks account, source and project authority. `claim` compare-and-sets the due time and rechecks that authority. `claimPublication` additionally matches the selected definition and returns scope atomically. `rollForward` loads stale definitions then performs one guarded claim per row; that loop reflects cron computation, not automatically an erroneous N+1.

Retain the existing atomic claims. Reuse the selected DTO in publication and avoid adding a second find or scope lookup. Measure stale-roll-forward batches and authority function/query work before proposing set-based changes. [V40](../../plowshare-server/src/main/resources/db/migration/V40__events_and_user_inbox.sql#L41) has the partial due-time index; evaluate adding the deterministic `name` tie-breaker only with representative plans. Optional bounded bulk compare-and-set could accept Java-computed next times as typed rows; a stored routine is useful only if it reduces actual round trips without replaying ticks.

Cache only display/configuration DTOs, keyed by database, schedule name, projection and durable definition version. Separate timing version because every claim advances `next_fire_at`; cache admission may be poor for frequently firing schedules. Add explicit versions and invalidate list/name dependencies after `define`, `pause`, `forget`, successful claims, roll-forward and file-managed edits, including cascades and other writers. Publish only after commit through the proposed tracked immutable DTO cache with bounded expected O(1) LRU. Current authorization remains authoritative; `due`, `claim` and `claimPublication` bypass shared cache. LISTEN/NOTIFY can wake due discovery, with timer wakeups retained for future deadlines and durable reconciliation after reconnect.

Mock tests should bound display refresh calls and prove reuse of the claimed snapshot. Focused future PostgreSQL tests cover competing claims, changed definitions, revocation, rollback and partial-index plans. Client schedule panels should keep valid state and refresh from scoped invalidations rather than reload unchanged lists.
