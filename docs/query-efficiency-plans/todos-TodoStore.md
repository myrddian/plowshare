# TodoStore

Status: Proposed. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[TodoStore](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/todos/TodoStore.java#L24) lists conversation-scoped rows ordered by parent/position/ID, inserts items and updates only when the previous `updated_at` still matches. TodoBoard owns whole-batch validation, 100-item limits, orchestration effects and post-commit notifications; TodoView reads the list. [V45](../../plowshare-server/src/main/resources/db/migration/V45__todos.sql#L35) already indexes conversation/parent/position. Check whether adding ID removes a material sort before proposing another index for a bounded list.

Confirmed reuse opportunity is [TodoBoard.apply](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/todos/TodoBoard.java#L273): it retains baseline/working item DTOs, writes them, then reloads the list after commit. Return an ordered immutable working snapshot only if the single-writer/no-trigger assumptions remain explicit and callback effects cannot alter it; otherwise document the required fresh read or return write projections. Batch inserts/updates to reduce up to one round trip per item, preserving per-item optimistic mismatch detection and all-or-nothing rollback. A stored batch function is optional if it maintains these invariants; individual UPDATE predicates must not disappear.

Track immutable TodoItem/list DTOs by database/conversation/projection and durable list generation, with item updated-at as the existing optimistic token, not a complete list-membership version. Cache admission requires a list generation covering insertions as well as updates. Depend on stage seed/status effects, compaction-linked notice views and conversation visibility. Cover TodoBoard mutations, stage seeding/orchestration and every database writer with after-commit invalidation; never publish working state before commit. Current access remains authoritative; cached locked/stage state cannot authorize a mutation. Reconnect bypasses uncertain lists until generation recovery. Use shared bounded LRU with the existing item/text bounds.

Mock one initial list read per batch and no unnecessary return reload where safe; test mismatch rollback and callback-driven changes. Changed batching/version SQL warrants focused PostgreSQL optimistic conflicts, atomic stage effects and insert/list invalidation tests. No runtime change is implemented.
