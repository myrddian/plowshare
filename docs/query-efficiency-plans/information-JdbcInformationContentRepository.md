# JdbcInformationContentRepository

Status: Proposed; no implementation. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Source](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/information/JdbcInformationContentRepository.java#L28) serves typed admission, catalogue content views and projection reuse. `head` resolves the newest ordinal by home/name with optional row locks. `binding` reads retained metadata then calls `types.attached` to resolve its contract. `view` reads revision policy/generation and performs separate reuse, stage-authorization and binding reads inside its mapper. Writes attach/redact bindings and authorize up to seven explicit processing stages under a live write fence.

**Confirmed query shape:** one content view requires several child queries, and every binding hydrates its contract again. Assemble one typed snapshot using bounded joined/aggregated projections or a table-returning function; reuse immutable decoded type contracts and the already-loaded revision generation. Batch stage authorization through typed rows/array input, retaining conflict and active-generation checks. Optional `RETURNING` can supply the authorized stage set. Do not erase lock-bearing `head` or `requireWrite` in favor of an earlier DTO.

[V143](../../plowshare-server/src/main/resources/db/migration/V143__authored_information_content_types.sql#L55) keys bindings by revision and protects immutability; [V144](../../plowshare-server/src/main/resources/db/migration/V144__information_projection_reuse_policy.sql#L6) keys stage authorizations. Home/name uniqueness and resource/ordinal uniqueness already support head resolution. Verify these plans before adding another index.

Track immutable binding DTOs by database, revision, type-version and metadata hash, and view projections by revision plus lifecycle generation and a separate authorization/reuse version. Generation alone does not advance for every metadata or stage-authorization change. Dependencies include type contract, retained binding, source availability/redaction, reuse provenance and stage authorization membership. Attach/authorise/redact, catalogue deletion/rebuild, projection copy and external writers must invalidate after commit. Protected bindings require current read/availability fences even when their contract is immutable. Locking reads and write authority stay uncached. Use the proposed bounded expected O(1) LRU and generation-fenced coalesced fills.

Mock budgets should establish a bounded content-view query count independent of stage count and no duplicate contract loads. Focused future PostgreSQL tests cover row-lock ordering, active-generation authorization, redaction during reads, stored-result equivalence and notification rollback/recovery. Clients should reuse the content DTO returned with status instead of immediately requesting it again.
