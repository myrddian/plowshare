# JdbcRelayOperationRepository

Status: Proposed; no implementation. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Source](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/JdbcRelayOperationRepository.java#L44) implements operator controls for `ProjectRelayOperations`. Receipt reads bind request ID to account/project/fingerprint. Apply inserts/locks that receipt, then locks consumer, topic generation and optional subscription generation in established order. It acknowledges an exact gap, reconciles/abandons an expected branch fence, or removes only empty/unleased/inactive metadata. Finally it updates receipt completion and rereads it. Prune uses bounded skip-locked receipt retention.

**Confirmed redundant result read:** completion update can `RETURNING` its status/seen/completed timestamp, combined with the already-validated request fields, instead of a final whole receipt reload. Reuse the locked topic/subscription state when nested broker actions need the same values under the same transaction, exposing a narrow typed transaction capability if necessary; do not bypass their invariant checks. Subscription removal separately tests lease and admission history; combine these into one typed eligibility projection if useful. Keep runtime configuration/remote receipt inspection outside database locks and retain current manager access even for cached receipts.

[V123](../../plowshare-server/src/main/resources/db/migration/V123__relay_operator_controls.sql#L28) supplies receipt identity/retention and topic/subscription incarnation UUIDs. Existing composite keys match occupancy checks. No new index is demonstrated. A typed control routine could reduce round trips, but only if it preserves generation conflicts, lock order, exact no-history requirements and audit/result atomicity.

Completed result DTOs are candidates keyed by database, account/project, request/fingerprint, action and result projection/version. Incarnation fields distinguish delayed requests from recreated names; do not use a receipt cache to skip them for a new mutation. Every apply completion/prune, project cascade and external receipt writer invalidates receipt entries after commit; broker topic/offset and delivery mutations invalidate their own display/list dependencies through all-writer hooks. Never cache manager authority, locks, removal eligibility or uncertain-resolution admission. Use proposed tracked immutable DTO/LRU and [delivery contracts](delivery.md); negative receipt hits must not hide a concurrent completion.

Notifications refresh operator views only; durable receipts, leases and reconciliation own correctness. Mock budgets should prove one final result projection and retained live authorization on receipt recovery. Later focused PostgreSQL tests cover request fingerprint conflicts, stale incarnations/fences, occupied removal, atomic rollback, lock ordering and notification loss. Mutating controls stay ordered under any asynchronous dispatch design.
