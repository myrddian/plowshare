# ConversationStore

Status: Proposed. Source baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[ConversationStore](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/ConversationStore.java#L575) owns creation, retained allowance relationships, individual/home/latest reads, owner/opening/hooks projections, lifecycle ancestry/tree traversal, retention roots and title/last-turn changes. Conversation controllers/frames, agents, retention and Board use these capabilities. `conversation_allowance_state` supplies current projected allowance state, not execution permission. Recursive queries deliberately stop at depth 64 and keep lifecycle on the root.

Confirmed extra hydration: `moveTo` performs a guarded update then `find`; `turnEnded` resolves/restores the allowance, stamps last-turn time and calls `find`. Evaluate a typed data-modifying CTE/`RETURNING` projection that joins the allowance view once, preserving root-only transitions and the live-orchestration exclusion. Failure-only reads that produce precise refusal reasons are justified. Reuse authorized conversation, owner and root snapshots within one valid operation instead of calling narrow helpers and full `find` again. Add bounded list projections/pages if callers need only display fields. [V17](../../plowshare-server/src/main/resources/db/migration/V17__conversation_origin.sql#L302) indexes home/origin/created time; compare lifecycle-filtered `(project_id,origin,lifecycle,created_at,id)` or a partial active index and `turns(conversation_id,agent)` for `latestFor` against real plans. Do not add duplicates blindly. A stored snapshot/transition function is optional if it consolidates this cohesive work.

Do not place [ConversationRecord](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/ConversationRecord.java#L90) directly in the immutable DTO cache: it contains live Budget/TurnCap objects and `find` attaches budget behavior. Introduce an immutable metadata/read-status projection with explicit allowance snapshot/version, separate from executable retained Budget. Key by database, conversation, projection and conversation/allowance generations; home pages include principal/filter/cursor and membership versions. Dependencies include root lifecycle, ancestry changes, last-turn/title/opening/hooks, project placement/name, allowance claims/ceilings and orchestration completion. Cover ConversationStore, TurnStore title stamping, allowance writers, Board/messaging and triggers after commit. Never cache claims or lifecycle admission as authority. Current account/scope/source visibility must fence protected reads; reconnect bypasses uncertain namespaces until durable recovery. Use the shared bounded expected O(1) LRU.

Deliver returned-projection/current-operation reuse first, then measured list/index work, then immutable versioned tracking. Mock that a transition response avoids redundant hydration while retaining allowance/lifecycle checks. Changed SQL/routines require focused PostgreSQL root/delegation depth, concurrent transitions, orchestration protection, shared allowance identity and rollback/invalidation tests. No runtime optimization is implemented here.
