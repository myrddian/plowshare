# JdbcFiringStore

Status: Proposed; no implementation. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Source](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/events/JdbcFiringStore.java#L80) owns the durable queue used by `Intake`, `Dispatcher` and scheduled publication. Reads include bounded compatibility preflight, ID lookup, target/busy/oldest waiting discovery and filtered reverse-arrival history. Writes admit deduplicated schedule ticks, board wakes, supersede excess queued work, claim/release/refuse/start/finish and recover abandoned work. Advisory transaction locks serialize scheduled trigger queues; a partial unique index prevents two unfinished starts per target.

**Confirmed extra round trips:** successful `arrive` and `owe` insert then `find` their own row. Use `INSERT ... RETURNING` with the existing validated mapper. `claimStart` first loads and validates a historical DTO; do not simply delete that read. Carry a validated candidate into an atomic claim or return and validate the claimed row within a transaction whose rollback preserves the pre-mutation validation guarantee. Keep conflict handling transaction-safe.

[V40](../../plowshare-server/src/main/resources/db/migration/V40__events_and_user_inbox.sql#L106) already covers tick uniqueness, target waiting and running exclusion. Evaluate partial `(trigger,arrived_at DESC,id DESC) WHERE status='queued'` for supersession and an expression-aware target ordering for message-continuation priority. These are candidates, not measured wins. Replace nullable-OR history predicates with bounded allowed query variants and consider keyset pagination. A typed claim routine could combine selection/validation/transition only with equivalent queue and concurrency semantics.

Do not cache busy checks, claims, queue caps, locks or unfinished ownership. Eligible terminal-history DTOs require database, firing ID, projection and durable transition version; final content still needs the current disclosure fence. After-commit invalidation must cover every transition, bulk recovery/refusal/supersession, board lifecycle writers and cascades, plus list membership. Depend on the proposed tracked DTO/LRU and durable change bridge; notifications wake queue discovery, while durable firings and timer/recovery sweeps remain authoritative. The source explicitly documents a multi-server caveat in `abandonUnfinished`; cache work must not obscure it.

Mock budgets should prove one write-returning round trip and no duplicate candidate loads. Future focused PostgreSQL tests cover duplicate ticks, competing claims, rollback on invalid historical DTOs, advisory ordering, partial uniqueness and notification loss. Measure queue discovery and client history independently from shared WebSocket dispatch delay.
