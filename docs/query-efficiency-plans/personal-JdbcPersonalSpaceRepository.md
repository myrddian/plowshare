# JdbcPersonalSpaceRepository

Status: Proposed. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[This repository](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/personal/JdbcPersonalSpaceRepository.java#L19) resolves personal project owner/ID/name, enumerates permanent USER accounts, checks service account kind, reserves a unique personal project, locks its row and marks initialization plus fixed manager membership. `PersonalSpaces` owns initialization/filesystem sequencing. The unique `personal_owner` introduced by [V95](../../plowshare-server/src/main/resources/db/migration/V95__personal_spaces.sql#L2) supports owner resolution; no additional lookup index is established as necessary.

First combine owner, ID and initialized status in a narrow typed snapshot when a single operation currently needs all three. Preserve the `FOR UPDATE` reserve read; the prior insert and service-account validation are lifecycle checks, not arbitrary refetches. Pass the returned reservation through initialization instead of resolving its ID again. PersonalSpaces.ensure checks serviceAccount before reserve checks it again; preserve pre-filesystem rejection while deciding whether a single authoritative admission under the reservation boundary can replace the repetition. A stored function could combine reservation checks/SQL if profiling supports it, but must retain filesystem transaction boundaries and fixed Personal ownership.

Cache only immutable identity projections under database, account/project identity, projection and durable project/account generation. Do not cache service-account eligibility or reservation locks as authority. Project/admin creation, account-kind changes, personal initialization and member writers must invalidate related values and account-list membership after commit. Return new versions with DTOs before shared admission; timestamps alone are not yet a defined version scheme. Current account and Personal access fences remain mandatory. On reconnect bypass until the relevant generations recover. Use the shared bounded LRU with protected scope keys.

Mock one reservation snapshot per initialization and failed-initialization retry behavior. A changed SQL/trigger contract needs focused PostgreSQL concurrent reserve, service-account refusal, rollback and membership invariants. No runtime change is proposed outside this owner and its existing lifecycle boundary.
