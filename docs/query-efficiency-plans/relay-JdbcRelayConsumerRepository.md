# JdbcRelayConsumerRepository

Status: Proposed; no implementation. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Source](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/JdbcRelayConsumerRepository.java#L28) implements distributed subscription ownership for `OwnedRelaySubscriptionWork`, native workers and approval inbox delivery. Acquire is one owner/expiry-guarded upsert `RETURNING epoch,lease_until`. Admit/claim lock and verify the lease before and after nested delivery transactions. Release compares worker/account/epoch. `requireLive` loads the lease `FOR UPDATE`, then separately obtains database `clock_timestamp` after waiting for that lock.

Repeated fences here have explicit concurrency reasons: row ownership can remain locked while real lease time expires during nested work. Preserve the final time check; neither an earlier allow result nor transaction-start time is sufficient. Measure clock-query and nested fence counts before combining them. A narrow stored function could lock the exact row, then sample clock after lock acquisition and return a typed live-lease result, reducing one round trip while preserving the timing guarantee. Avoid moving routing/provider IO under those locks. [V122](../../plowshare-server/src/main/resources/db/migration/V122__relay_consumer_leases.sql#L3) supplies the exact composite lease key; no additional index is justified for point operations.

**No shared cache for lease state, epochs, admission or ownership checks.** Keep the acquired immutable lease DTO in request-local memory as the expected fence, not as proof it is still live. If operator display snapshots later use this owner, key them by database, scope/topic/subscriber incarnations and epoch plus a separate renewal version; require current project access and document their observational staleness. Acquire/release, subscription deletion, operator removal and project cascades invalidate display dependencies after commit. Lease epoch already changes on acquire but release changes expiry without changing epoch. Use the proposed tracked DTO/LRU only for such explicitly introduced display projections.

Notification hints may wake a contender on release, but database expiry deadlines and durable reacquisition remain mandatory after missed signals/reconnect. Follow [delivery contracts](delivery.md) rather than turning hints into ownership grants. Mock budgets should distinguish intentional fences from repeated decoding. Focused future PostgreSQL tests cover waiting past expiry, reassignment, stale release, nested rollback and routine timing semantics. No effect may replay because a cached lease or notification appears absent.
