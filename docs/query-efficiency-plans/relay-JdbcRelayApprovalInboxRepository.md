# JdbcRelayApprovalInboxRepository

Status: Proposed. Source baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[This owner](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/JdbcRelayApprovalInboxRepository.java#L74) discovers requested/resolved approval topics, pages missing or unsettled Inbox obligations, advances lease-fenced offsets, records gap recovery and prunes recovery audit. DurableRelayApprovalInbox reconciles retained approvals before consuming publications; acknowledgement is availability bookkeeping, not evidence that a person saw a push. The two `requireOwned` calls around cursor mutation are deliberate lease fences.

The `MISSING` predicate repeats owner resolution and Inbox probes for the same approval; `ready` also converts each approval project ID to a concatenated scope string. Evaluate one bounded candidate relation joining conversation owner once and a lateral/aggregated Inbox projection reused by the missing/retry conditions. Compare a topic-driven numeric project join against the expression predicate. [V152](../../plowshare-server/src/main/resources/db/migration/V152__approval_inbox_recovery.sql#L3) already indexes pending project/ID; [V153](../../plowshare-server/src/main/resources/db/migration/V153__approval_alert_retry.sql#L4) indexes open approval alert attempts. Preserve the existence semantics for already read/settled notices and cursor ordering. A table-returning discovery routine is useful only if it removes duplicated work. No measured SQL latency is established for this owner.

Initially exclude discovery eligibility, retry timestamps, consumer leases and advances from shared caching. An immutable recovery-audit DTO could later use database/scope/topic/subscriber/boundary/projection keys, but prune and collection membership still need generations. Reuse already loaded approval/recipient snapshots within one valid delivery operation; do not cache a pending decision as current authority. Every approval answer, Inbox insert/read/settle/alert-attempt, conversation owner change, Relay append/offset/gap and prune writer must publish after-commit invalidation or wake evidence. LISTEN/NOTIFY can wake bounded discovery; alert retry and lease expiry still need timers/reconciliation, and approval rows remain the recovery authority. Reconnect bypasses uncertain snapshots and resumes durable scanning as described in [delivery](delivery.md).

Deliver candidate consolidation and query budgets first, notifications later; use the shared bounded LRU only for justified audit projections. Mock bounded discovery and preserved failed-recipient reconciliation. Changed SQL/notifications require focused PostgreSQL requested/resolved equivalence, duplicate notices, lease loss around advance, gap recovery, rollback and timed retry tests. Never replay approval effects because a notification or cache entry is absent.
