# JdbcRelayRepository

Status: Proposed; no implementation. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Source](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/JdbcRelayRepository.java#L54) implements the broker log for `DurableRelay`, scheduled/source publishers and maintenance. Topic registration/configuration lock topic rows. Append locks the topic, checks retained event identity, advances position and inserts in one transaction. Subscribe inserts then loads its existing/new offset. Read loads topic and subscription, then a bounded ordered publication prefix with cumulative byte budgeting. Unread derives its count from contiguous suffix boundaries. Advance/gap acknowledgment and retention pruning serialize against that same topic lock.

Reuse the locked typed topic/subscription snapshots through helpers; these reads establish coherent bounds, so replacing them with unfenced RAM values would break gap/retention semantics. Subscribe can use a conflict-safe returned offset projection, preserving existing subscription state rather than overwriting it. A typed broker-page function could return topic/offset/publications in fewer round trips, while retaining shared locks and contiguous byte-limited prefixes. Append already constructs its result from validated written fields; do not add a find-after-write.

[V117](../../plowshare-server/src/main/resources/db/migration/V117__relay_log.sql#L15) supplies ordered position and retained-event uniqueness; [V120](../../plowshare-server/src/main/resources/db/migration/V120__relay_scopes.sql#L20) converts their first key to scope. Existing keys match reads; assess prune discovery joins before extra timestamp indexes. Historical deployed Relay reads were tens of milliseconds; approximately two-second waits behind facets demonstrated queue coupling, not inherently slow broker SQL. Coordinate bounded independent-read dispatch and client state reuse through [delivery contracts](delivery.md).

Track immutable publication DTOs by database, scope/topic **incarnation generation**, position/event ID and projection. A publication is immutable while retained, but a cache must respect current retention/deletion and authorization before disclosure. Topic metadata keys need policy version, last position and expired boundary; incarnation UUID alone is not a mutation version. Subscription projections also need offset/version in addition to incarnation. Register/configure/append/subscribe/move/prune, delivery admission offset writes, native/approval adapters, operator removal and project cascades must invalidate item and collection dependencies after commit. Cache neither locks, append allocation, current offset authority nor gap admission. Use proposed bounded tracked DTO/LRU with payload byte limits and generation-fenced fills.

LISTEN/NOTIFY should wake scoped publication readers across processes; retain durable positions, offsets and time-driven retention/recovery sweeps. Mock budgets should prove reuse of one coherent broker snapshot. Later focused PostgreSQL tests cover append rollback/idempotency, eviction/read races, byte prefixes, current access revocation, removed/recreated topics and notification recovery.
