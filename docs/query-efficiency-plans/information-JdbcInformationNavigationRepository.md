# JdbcInformationNavigationRepository

Status: Proposed; no implementation. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Source](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/information/JdbcInformationNavigationRepository.java#L29) implements `InformationNavigationRepository` for `DocumentNavigation`. It resolves account/management authority, inherited policy, current heads, document/facet selections and neighbour disclosure; writes version-guarded policies/relationships/saved views plus receipts/audit. Read snapshots explicitly use repeatable-read read-only transactions. Policy transitions serialize navigation and compare retained restrictions; writes preserve authority-before-resource ordering.

**Confirmed amplification:** `facets` always requests the eight ordinary and two content-type facets plus graph and total: 12 repeated selected head/permission queries. Share one authorized `MATERIALIZED` candidate selection, coordinated with the catalogue facet implementation. `relationships` pages visible edges then calls `relatedSelection` per edge, potentially adding readability, reference-visibility and label queries. Return bounded edge-plus-neighbour DTOs in one set-based query while filtering hidden neighbours before paging and stripping pinned revisions for locked placeholders. Request-local maps can deduplicate repeated neighbour/head/policy resolution within one snapshot. Policy lookup separately fetches settings/version and resolves inheritance repeatedly; load one typed policy chain. `setPolicy` evaluates effective policy per affected resource before/after mutation; a set-based bounded comparison can replace per-resource calls without weakening widening refusal. `save` immediately rereads the saved view; use guarded write `RETURNING`.

[V147](../../plowshare-server/src/main/resources/db/migration/V147__document_navigation_policy.sql#L22) already indexes active source/target graph endpoints and obligations by source. Evaluate endpoint-plus-edge-ID/relation and account/saved-view order against representative plans. A typed graph-page or policy-comparison function is useful if it returns bounded DTO projections; it must retain [current V172 readability](../../plowshare-server/src/main/resources/db/migration/V172__substrate_knowledge_reads.sql#L79).

Cache immutable saved-view/relationship DTOs using their existing versions; policy DTOs need own and inherited ancestor versions. Keys include database, principal, full selection/read boundary, direction/relation/filter/page, pinned revision and projection. Graph/head/query-set membership and obligation retention are dependencies, including new edges or previously hidden neighbours. Policy/create/remove/save/delete/record, catalogue head/audience/redaction, membership/account changes, obligation triggers and external writers invalidate after commit. Never cache manager grants, locks or write admission. Current disclosure fences remain mandatory; asynchronous invalidations cannot preserve revocation by themselves. Use proposed tracked DTO/LRU bounds, broader namespace invalidation for excessive graph fan-out and durable recovery.

Mock budgets should make relationship-page query count independent of edge count and facet candidate evaluation constant. Later focused PostgreSQL tests cover locked/unavailable distinctions, paging, inheritance widening, concurrent versions, atomic audit, revocation and notification races. Preserve client graph state and refresh only affected selections.

Coordinate live permission evaluation with the [readability-function workstream](readability-functions.md) and apply the shared [delivery contracts](delivery.md).
