# JdbcRelayExecutions

Status: Proposed; no implementation. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Source](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/relay/JdbcRelayExecutions.java#L24) retains start intent independently from broker cleanup for `WorkRelayReceiver`. `begin` inserts execution evidence only from an exact live DISPATCHING delivery fence. `accepted` records an idempotent matching job/orchestration receipt and conversation. `find` selects receipt metadata by request/account/project. `prune` bounds deletion to accepted old executions whose conversations are closed/gone and whose deliveries have been removed. Absence of a receipt never authorizes replay.

These are already narrow, atomic statements with no established internal redundant read. Keep the receipt returned by an owning start/accepted transition in memory for the response instead of adding a lookup. Work receiver intentionally resolves current route/account access before recovering a known receipt; preserve that security boundary. [V121](../../plowshare-server/src/main/resources/db/migration/V121__relay_work_receipts.sql#L15) supplies request identity and project/conversation lifecycle. Consider a partial `(accepted_at,request_id) WHERE accepted_at IS NOT NULL` retention index only if representative pruning plans warrant it. No stored procedure is justified for the existing point writes.

A terminal accepted DTO can be tracked by database, account, project, request UUID and receipt tuple/version. Accepted fields are idempotent but conversation deletion sets its foreign key null, so the complete DTO is not immutable forever. Add explicit durable change/version evidence before caching it. Begin/accepted/prune, conversation deletion, project cascades and external writers invalidate positive/negative receipt dependencies after commit. Never cache missing receipt as proof of no effect, open intent, dispatch fences or live route authority. Use proposed bounded expected O(1) LRU only behind a typed receipt read, preserving current authorization.

Notifications may refresh diagnostic receipt views; they cannot replace owning reconciliation or execution evidence. Follow [delivery contracts](delivery.md). Mock tests should ensure receipt recovery avoids a second effect while still checking authority. Focused future PostgreSQL tests cover begin/accept races, matching receipt idempotency, prune eligibility, conversation deletion, rollback and notification recovery. No performance plan should turn an unreceipted intent into retryable work.
