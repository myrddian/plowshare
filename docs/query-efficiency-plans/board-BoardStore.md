# BoardStore

Status: Proposed. Source baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[BoardStore](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/board/BoardStore.java#L126) handles topics/tree lifecycle, projected allowances, messages and replies, decisions, seats/watermarks, notices and durable wake inspection. Board, BoardDelivery, SeatRunner and inspection frames consume it. Messaging transport topics are intentionally excluded from public board lists. Allowance claims use independent transactions and cannot be satisfied by a cached balance.

Confirmed waste: `openRoot`, `openChild` and `post` insert then reload; use typed `RETURNING`/a CTE joining current allowance state where needed. `topup` calls `lockTopic` (which already reads a topic) and then reads it again: use the returned locked snapshot before changing the allowance. `summaries` executes two correlated message counts per topic; aggregate both with FILTER once for the selected page. `inspectSeats` selects a latest firing per seat using LATERAL; evaluate a bounded ranked firing relation and matching `(topic,target,arrived_at,id)`/active predicate indexes using real plans. `markQuiet` repeats the latest eligible message subquery; a materialized single-candidate CTE can feed both comparison/update. Preserve topic locks and monotonic message-sequence comparisons in seen-watermark updates. Stored routines are candidates for cohesive topic/post/notice transitions, not for bypassing Board policy.

Track immutable BoardMessage and decision DTOs first, keyed by database/topic/message/projection and durable message version; sequence supplies ordering but needs a defined immutability/maintenance contract. Topic/status/seat summaries need separate generations covering lifecycle, allowance and firings. Keys include account/project filters and page bounds; dependencies include new messages and topics, message kind/count membership, seats/seen state, decisions, notices, firings and messaging transport exclusion. Cover BoardStore, BoardMessaging, firing/allowance writers and database triggers with after-commit invalidation. Do not cache topic locks, claims, alert admission, current balances or active-wake checks as execution authority. Current project/conversation visibility must fence protected views. Reconnect bypasses mutable views until durable recovery; use shared bounded LRU with body-size admission.

Implement returned-row/reuse and aggregate changes before cache integration. Mock no post-write reload and bounded list query counts, plus preservation of private messaging exclusion. Changed SQL warrants focused PostgreSQL reply-topic constraints, monotonic seen progress, topup/close races, independent durable claims, atomic notices and rollback/invalidation tests. The earlier isolated Relay timing does not measure BoardStore performance.
