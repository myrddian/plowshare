# JdbcPassageRepository

Status: Proposed. Source baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Passage persistence](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/archive/JdbcPassageRepository.java#L33) polls up to eight repair sources, manages retry/repair admission, publishes up to 16 passages under owner-before-queue locks, ranks entry/digest candidates, and aggregates coverage. PassageIndex/ConversationSearch own embedding calls outside repository locks. ReadScope filtering, digest safety and knowledge-only exclusion occur before candidate limits; preserve that ordering.

Confirmed write amplification: `publishBatch` executes one insert per passage after checking locked source hash/generation/position. Use JDBC batch insertion or a bounded typed SQL function while retaining the same transaction and row mapping. Owner lock and queue revalidation are legitimate freshness reads, not cache candidates. Return source home/owner metadata with a repair-source DTO if callers immediately request `sourceHome`, `logOwner` or `digestHome`; retain authoritative checks at publication. Coverage repeatedly probes passages using correlated EXISTS/counts: compare a pre-aggregated passage relation under identical fences. Ranking's profile-specific exact/ANN candidate bounds must remain explicit. [V79](../../plowshare-server/src/main/resources/db/migration/V79__retrieval_passages.sql#L3) has source/passages keys and a pending index; its original exact-search decision does not justify assuming later embedding-profile plans are efficient. Measure actual generated column/operator/index matches before adding ANN or partial retry indexes.

Track immutable passage/source-text snapshots under database, source type/ID/hash, embedding generation/space/slot/revision, projection and read scope. Defensive-copy vectors. Shared result/coverage caching additionally needs home/principal/query/profile/limit keys and collection generations for all eligible sources, including newly ready or withdrawn rows. Do not use source text hash as the version of mutable indexing status or vectors. Dependencies span entry ejection/privacy, conversation home, digest dirty/refresh, retrieval publication/failure and embedding-slot cutovers. Every owning writer/trigger publishes invalidation after commit. Current visibility and source-generation checks remain authoritative; no cached repair claims, queue locks or retry admission. Reconnect bypasses affected namespaces until durable recovery; use shared bounded LRU/admission.

First batch publication and reuse repair DTO metadata; second optimize coverage/ranking plans; third add eligible tracking. Mock query budgets independent of passage count, generation-aware reuse and stale publication refusal. Changed SQL needs focused PostgreSQL owner/queue lock ordering, invalidation during fill, exact/profile ranking equivalence, withdrawal and rollback tests. Provider I/O must remain outside database locks.
