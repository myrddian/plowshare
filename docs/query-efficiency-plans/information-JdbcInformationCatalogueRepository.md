# JdbcInformationCatalogueRepository

Status: Proposed; no implementation. Baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[Source](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/information/JdbcInformationCatalogueRepository.java#L55) implements `InformationCatalogueRepository` for `InformationCatalogue`, portable bundles and event publication. Read groups cover row/metadata/readability; steps/progress/events/inputs/report/citations; text/bytes/code spans/outlines/symbols; authorized list/facets/inventory/event cursor/evidence. Mutations cover admission, links/audience, availability/deletion, rebuild/cancel/allowance, tags/groups, evidence/reports and request/command receipts. Authorization, current-root policy, dependency validity and lock order are part of each operation's contract.

**Confirmed waste:** `readable` selects a full metadata row then discards it; status immediately loads metadata again and `row` loads extracted text merely to use owner/generation. Return an authorized narrow typed snapshot and pass it through helpers. Split text/bytes from metadata. Progress uses two aggregate statements; combine only when the caller needs both. `facetCounts` independently repeats the same expensive authorized candidates: eight ordinary facets plus graph and total make 10 queries; typed views add two facets, making 12. Use one bounded `MATERIALIZED` candidate CTE with aggregate branches, or a typed table-returning facet function. Resolve distinct authority/dependency sets once in that valid snapshot. Catalogue event insertion also repeats global/personal/project permission traversal across every account; coordinate its set-based recipient selection with the event repository plan.

Prior `b96f260` deployment measured the 12-query typed manual facets about 1.1 s global and 1.9 s personal; those are historical measurements, not current-branch benchmarks. Preserve that provenance. [V172](../../plowshare-server/src/main/resources/db/migration/V172__substrate_knowledge_reads.sql#L59) is the current root-read authority baseline. Event history filters revision then orders sequence; evaluate a new `(revision_id,sequence)` index because [V83](../../plowshare-server/src/main/resources/db/migration/V83__information_lifecycle.sql#L64) has sequence identity alone. Existing tag GIN indexes do not cover the joined, dynamically rebuilt text-search expression: design an owning maintained search projection, updating all contributing metadata/text writers. Keep indexes/routines in new migrations.

Track content by database/revision/hash/projection; track mutable metadata/heads/facets by explicit durable version plus principal, full selection, facets/corpus/read boundary and pagination. Generation alone misses tags, policy and other updates. Dependencies include resource membership, type binding, inputs/references, current heads, policies/grants/accounts, reports, stages, document projections and embedding slots. Every listed mutation plus processing/projection/content/navigation/policy writers and cascades must publish after-commit invalidations. Shared notifications cannot authorize immediate revocation; use current authority fences. Claims, write locks and command leases remain uncached. Use the proposed bounded tracked DTO/LRU, with oversized content bypass and fill-generation fencing.

First deliver projection/reuse and set-based SQL; then shared versions/invalidation, clients and independent read dispatch. Client lists should render without waiting for facets and coalesce unchanged refreshes. Mock budgets should prove one authorized snapshot and one candidate selection per facet result. Future focused PostgreSQL tests cover result equivalence, dependency revocation, deletion/redaction, routine/index plans and notification races; separately measure SQL, queue and render latency.

Follow the shared [readability-function workstream](readability-functions.md) for live authority optimization and the [delivery contracts](delivery.md) for versions, invalidation coverage and bounded dispatch.
