# JdbcBoardMessagingRepository

Status: Proposed. Source baseline: `fc36351f239b62984363ababaa1de1139402aafb`.

[The messaging repository](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/board/JdbcBoardMessagingRepository.java#L56) owns instances/defaults, route state and idempotency, external ingress contexts/tasks, pending/deadline queries, request/conversation/address locking and firing recovery. BoardMessaging composes those primitives with BoardStore. It is separate from Relay's publication/subscriber ledger.

Confirmed N+1 behavior is in [BoardMessaging.listing/view](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/board/BoardMessaging.java#L1304): one instance list becomes per-row `instanceJob`, `awaitingAny`, `pendingCount` and `instanceState` calls, plus visibility checks. Supply one bounded typed inspection projection using page-first instance selection and aggregated route/firing state. Preserve raw-row paging before visibility filtering, which prevents withheld rows hiding subsequent pages. [Delivery composition](../../plowshare-server/src/main/java/io/aeyer/plowshare/server/board/BoardMessaging.java#L1422) similarly resolves each route, sender/recipient, job/state and Board message: batch authorized delivery DTOs and reuse repeated participant snapshots. Keep current authorization and uncertain-send reconciliation.

[V93](../../plowshare-server/src/main/resources/db/migration/V93__board_direct_messages.sql#L21) has pending/final-reply/idempotency indexes; [V94](../../plowshare-server/src/main/resources/db/migration/V94__message_continuations.sql#L16) adds deadline filtering. Inspect expression indexes for executed `firings.data->>'direct_message'`/`message_approval` predicates and `(reply_to,posted_at)` join plans before adding duplicates. A table-returning inspection function is reasonable if it replaces per-row work. Keep conditional mutations and transaction locks authoritative. Notifications may wake recovery/expiry discovery with periodic reconciliation; time deadlines still need scheduled wakeups.

Cache immutable read DTOs keyed by database/account/project/instance or message, projection/filter/page and durable route/instance/firing generations. Message body identity can be shared with BoardStore's typed owner, avoiding two body caches. Dependencies include defaults, archive/active flags, route pending/started/awaiting/handled/termination/deadline, replies, participant visibility, approval answers, firings and external-task membership. All BoardMessaging, BoardStore, approval/firing/allowance and external-ingress writers invalidate after commit. No cached absence or state permits send/claim/handling/default selection; current revocation fences remain required. Reconnect bypasses uncertain namespaces until durable recovery; use the shared bounded LRU with no credential/context leakage.

First batch inspections/deliveries and reuse participant DTOs; second tune indexed recovery queries; third add tracking and wakeups. Mock list query budgets independent of page length and sender/recipient deduplication. Changed SQL requires focused PostgreSQL one-handler/final-reply uniqueness, address lock races, ingress receipts, timeout/approval recovery and rollback/invalidation tests.
