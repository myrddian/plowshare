# First query-efficiency slice

Status: implemented locally on 2026-10-19. Deployment and production UI
verification are separate. This implements the first slice of the
[delivery plan](query-efficiency-plans/delivery.md), building on the
[measured audit](query-efficiency-analysis/README.md).

## Facets reuse one authorized candidate set

Catalogue and navigation facets now execute one PostgreSQL statement instead of
10 or 12 aggregate statements. A materialized candidate CTE applies the existing
selection and readability predicate once, then supplies total, dimension and
tag-graph aggregates. The typed variant retains its content-type binding joins.
Large extracted text is used by search predicates when requested but is excluded
from the materialized projection.

The query preserves catalogue revision selection, navigation head selection,
private tag visibility, duplicate values, database ordering, dimension limits
and graph limits. All aggregates now share one statement snapshot. Authorization
functions retain their current implementation and run on each request; there is
no retained authorization cache or schema migration. Repository callers still
receive typed facet DTOs.

## Lists render while facets are pending

The desktop collection view submits its list first and owns facet work
independently. A pending facet response cannot delay list rendering, and a facet
failure has a separate status without removing a successful list. Repeated
refreshes coalesce an already pending facet request for the same context.

Connection, selection, scope, view and filter fences reject stale responses.
Changing context clears old facet options, graph and totals. This is pending-work
reuse; retained DTO caching and replacement of the existing refresh timer remain
later work.

## Independent reads have bounded dispatch

Segmented connections permit audited independent reads to overlap. The allowlist
covers information lists, facets, reads, document gets, navigation capabilities
and relationship lists; Relay topics/log; and schedule lists/files. It excludes
search, waits, subscription changes, leases, cursor changes and acting-context
requests. Information status remains ordered because its hidden-read fallback
can acquire write-admission locks.

Every other frame is an ordering barrier, including unknown operation types and
malformed envelopes. A barrier waits for earlier reads and completes before later
reads or writes start. Classification schedules work only; the normal handler
still validates the operation payload and authorizes at execution time. Read
responses may finish out of order and retain ordinary request correlation.

Capacity defaults to two reads per connection and eight across the event
handler, configured through `plowshare.transport.event-read-concurrency` and
`plowshare.transport.event-read-global-concurrency`. A fair global permit is
acquired before starting a worker. Existing request count and memory bounds
include work waiting for capacity and active work. Closing a connection discards
unstarted work and releases its reservation without interrupting or replaying
running operations. Legacy JSON dispatch remains inline. See the
[transport decision](decisions/0009-segmented-sdk-message-transport.md).

## Measured SQL improvement

The old typed catalogue facet bundle and the new generated statement were run
against the same live manual data using PostgreSQL 16.15, three repetitions per
variant and scope, on 2026-10-19. Each case used a read-only transaction and
`EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`; the old figure sums the execution times
of its 12 statements. Parameters and operational plans remain private.

| Manual selection | Old median SQL execution | New median SQL execution | Reduction |
| --- | ---: | ---: | ---: |
| Global-read scope | 1,054.384 ms | 89.443 ms | 11.8 times |
| Personal scope | 1,841.136 ms | 161.984 ms | 11.4 times |

The comparison uses the old repository implementation from `0ec085a417ffa1503c854f2e145c0da881d3450f`
and SQL generated by the new repository with identical inputs. The running
service was unchanged. These are database execution measurements, not deployed
end-to-end latency or a guarantee at larger cardinalities. Existing slow
readability functions still warrant their own optimization; this slice removes
their repeated evaluation across aggregates.

## Verification

Focused mocked tests cover one-statement facet binding and mapping, concurrent
reads, per-connection and global limits, ordered barriers, permit and memory
release, and malformed-frame classification. Existing channel and packet tests
cover the surrounding transport behavior.

Nine focused PostgreSQL tests passed: seven new aggregation cases and two
existing facet cases. They verify materialized predicate reuse, typed/legacy
dimensions, live permissions, head/revision and relationship selections,
duplicate values, empty results, ordering and truncation. Malformed null tags
retain their prior behavior: catalogue DTO mapping rejects them and navigation
omits them.

Client tests use deferred promises to verify independent list rendering, facet
failure handling, pending-work reuse and stale-response rejection. A supplemental
real-browser DOM smoke test covers these behaviors through the installed view,
including preservation of a document draft. The ordinary test suite remains
browser-free.

Repository `format` and `formatCheck` passed. The complete non-database
`check --continue --max-workers=1` passed, including 5,974 server tests. An earlier
parallel run encountered an existing process-withdrawal timing failure; that
test passed in isolation and in the final repository run. Separate test
invocations must run serially because they share the same result directory.

The bounded LRU cache, tracked database DTOs, notification invalidation bridge,
Relay polling changes, indexes and stored-function improvements remain separate
slices under the broader strategy.
